## 0. 一句话

把「服务器 / 数据库 / 埋点」三块状态收进后台一页（人看 ✓），再让 AI 基于**只读聚合数据**做问答与简报（AI 看 ✓）；
**AI 永不直接改生产** ✗ —— 它只能给建议，执行必须由人在后台点。

| # | 边界 | 理由 / 出处 |
| --- | --- | --- |

| 7 | 后台自身**不挂公网**（保持内网/隧道访问） | `admin/02` 既有结论 |

## 1.1 D2 =「不脱敏」的代价与配套（**做 M3 前必读**）

**为什么放宽**：本项目真正要回答的是「**用户在问什么、AI 答得对不对**」—— 只看聚合量（计数/比率）
永远答不了这类问题，只能看原文。所以这是理性选择，不是疏忽。

**代价（诚实列出）**：

1. **第三方处理 + 数据出境**：对话原文会送到第三方大模型 API（DeepSeek / 百炼），
   内容**离开我们的服务器**，我们**无法控制其后续存储与处理**；
2. **告知义务**：用户原本的理解是"我的提问只用于生成回答"，现在多了"运营分析"这个用途
   → 属于**处理目的变更**，必须告知（见下"配套 1"）；
3. **成本**：送原文比送聚合量贵得多（token 按字数计）→ 必须抽样 / 按需 / 摘要化。

**必须同时满足以下 4 条，缺一条就不上 M3**：

| # | 配套 | 具体做法 |
| --- | --- | --- |
| 1 | **先更新用户须知并递增版本**（`../web/15` → `v1.1`） | 在"第三方服务与数据处理提示"一条里明确：**对话内容可能被用于运营与质量分析**。版本一递增，**所有用户会被要求重新阅读并确认**（机制已上线 ✓）。⚠️ **声明先上、分析后开** —— 顺序不能反 |
| 2 | **只在后台、只在服务端** | 不新增任何"面向浏览器"的对话原文接口；上下文在服务端组装后直接送 AI 服务 |
| 3 | **抽样 / 按需 / 摘要，不做全量** | 默认只分析"异常会话 + 抽样会话"；单次分析设有 token 上限；分析结果**缓存为摘要**，避免同一会话重复送原文 |
| 4 | **留痕可审计** | 每次分析记录：范围（时间窗 / 会话数）、送出的 token 量、模型、时间 → 落 `ai_analysis_runs` 表，后台可查 |

> 另：`../web/15` 里已经写明"**请不要提交任何个人隐私、账号凭据、商业秘密**" —— 它本来就在降低
> "原文里带敏感信息"的概率，但仍然不能当作脱敏手段 ✗。
> 如果将来想收紧，最省事的折中是：**送原文前跑一层轻量规则**（手机号 / 身份证 / 邮箱 / 游戏 UID 打码），
> 一句话就能加，不影响分析效果 —— 建议在 M3 实现时顺手加上（**属可选项，由你定**）。

## 2. 三块观测的取数方案（核心：**谁能看到什么**）

> 这一节是本文最值钱的部分 —— 它决定了哪些指标**现在就能做**、哪些**必须加组件**。

### 2.1 服务器状态（ECS）

| 指标 | 数据源 | 可达性 |
| --- | --- | --- |
| 三容器状态 / 健康 / 镜像 tag | `docker compose ps`（**宿主机**） | ✗ 容器内看不到宿主机 Docker |
| 主机 CPU / 内存 / 负载 / 磁盘 / 网络 | `/proc`、`/sys`、`df`（**宿主机**） | ✗ 容器内只看到**容器自身**的限额视图 |
| 外层 Nginx 状态、**证书到期时间** | `/etc/letsencrypt/live/…`（**宿主机**） | ✗ 同上 |
| 站点对外可用性（HTTP/HTTPS 探活） | 主服务自己发请求 | ✅ 容器内可做 |
| DB 连接、RDS 可达性 | 主服务已有连接 | ✅ 容器内可做 |

**结论**：服务器状态要完整，**必须有一个宿主机侧采集器**（M2）：
一个只读 shell 脚本（读 `/proc`、`docker stats`、`df`、`openssl x509 -enddate`）由 **cron / systemd timer** 定时执行 →
`POST /internal/v1/admin/ops/host/metrics`（带 `X-Internal-Key`）。
**不引入** cAdvisor / node_exporter / Docker socket 挂载 ✗ —— 个人项目不值得，且挂 socket 等于给容器宿主机权限 ✗。

### 2.2 数据库状态（RDS MySQL 8.0.36）

| 指标 | 可达性 | 说明 |
| --- | --- | --- |
| **连接池**：open / in-use / idle / wait | ✅ 主服务 `sql.DBStats()` | 最能反映"服务健康"的一组 |
| Ping 延迟 / 慢请求计数（应用侧计时） | ✅ 主服务 | 应用视角的"慢"，比 DB 侧慢日志更贴业务 |
| 库内表**行数与占用**（`information_schema`） | ✅ 应用账号可查 | 表增长趋势、异常突增 |
| 事件落库延迟（埋点 worker 队列深度、最后写入时间） | ✅ 主服务 | 埋点是否"活着" |
| `SHOW GLOBAL STATUS` / 慢日志 / 复制状态 / 实例磁盘水位 | ✗ **应用账号权限不足** | 账号 `teyvat` 只授了 `teyvat_guide.*`；这类需要 PROCESS 等全局权限 |
| 实例级指标（CPU/IOPS/连接数上限/磁盘） | △ 阿里云控制台（人工 ✓）/ OpenAPI（需只读 AccessKey） | **v1 走控制台链接；v2 再评估 OpenAPI** |

**结论**：数据库这块 v1 = **应用视角指标 + 控制台深链**（面板上给一个"打开 RDS 控制台"按钮 ✓），不引入新凭据 ✓。

### 2.3 埋点与业务指标（**已落地** ✅）

`usage_events` / `usage_daily` / `chat_messages`（token 分 cached / 未命中、降级率、无关问题、会话与提问量）
—— 取数与看板口径见 `../shared/07` 与 `06-对话记录查看设计.md`，本设计只负责"汇总到一个总览 + 喂给 AI"。

## 3. 接口契约（草案，全部只读 + `X-Internal-Key`）

| 接口 | 用途 | 备注 |
| --- | --- | --- |
| `GET /internal/v1/admin/ops/overview` | **一次拿全**：站点探活 / 容器 / DB / 证书 / 磁盘 / 告警灯 | 面板与 AI 共用同一份聚合，避免两处口径漂移 |
| `GET /internal/v1/admin/ops/db` | 连接池 + 表增长 + 落库延迟 | 应用视角 |
| `GET /internal/v1/admin/ops/host` | 宿主机指标（最近一次上报） | 由采集器推送 |
| `POST /internal/v1/admin/ops/host/metrics` | 采集器上报入口 | 带 `X-Internal-Key`；**只接受白名单字段** |
| `GET /internal/v1/admin/ops/alerts` | 当前告警规则与状态 | 复用 P4.4 的"进程内评估 + 冷却 + 恢复通知"口径 |
| `POST /internal/v1/admin/ai/ask` | AI 问答（问题 + 允许的指标上下文） | 内部调 AI 服务 `/v1/complete`，**不暴露给浏览器以外的调用方** |
| `GET /internal/v1/admin/ai/reports` | 简报列表（每日/每周） | 含生成时间、依据指标、结论正文（标注 AI 生成） |

**响应体纪律**：只含**聚合量与标识符**（事件名、计数、比率、延迟、表名）——**不含对话正文 / UID / 用户名** ✓。

## 5. 告警规则（复用现有通道，不新造轮子）

| 规则 | 阈值 | 级别 |
| --- | --- | --- |
| 站点探活失败 | 连续 2 次 | 🔴 高 |
| 容器不健康 / 重启 | 任意不 healthy；重启 >3 次/小时 | 🔴 高 |
| **证书到期** | < 14 天 | 🟠 中（续期失败时才算高） |
| 磁盘占用 | > 85% | 🔴 高 |
| 内存 / 负载 | 内存 > 90%；负载 > 核数 × 2 | 🟠 中 |
| DB 连接池使用率 | > 80% | 🟠 中 |
| DB 表增长异常 | 周环比 > 50%（且绝对量 > 10 万行） | 🟡 观察 |
| 埋点落库延迟 | > 5 分钟无写入 | 🟠 中 |

投递：**日志 + webhook**（复用 `ai/04 §8.3` / P4.4 既有机制 ✓）。

## 7. 明确不做

| 事项 | 原因 |
| --- | --- |
| AI 直接改生产 / 自动重启服务 / 自动改配额 | 越权风险远大于收益 |
| 把对话正文 / UID / 用户名送进模型 | 隐私与合规 |
| 后台挂公网 | `admin/02` 既有结论 |
| 引入 Prometheus + Grafana + node_exporter 全家桶 | 个人项目规模不需要；先用现有接口 + 一页看板 |
| 应用账号去要 RDS 全局权限 | 破坏最小权限原则；实例级指标看控制台即可 |
