## 1. 项目概况

「AI 提瓦特向导」（teyvatGuide）是一个面向 C 端用户的《原神》智能助手工具站：

| 项 | 说明 |
| --- | --- |
| 技术栈 | Go Gin + React SPA + GORM + MySQL（独立库 `teyvat_guide`） |
| 鉴权 | C 端 JWT；管理接口用 `X-Admin-Key` 静态密钥 |
| 已有管理 API | `POST /api/admin/assets/import`、`GET /api/admin/assets/missing`、`POST /api/admin/assets/reload` |
| 健康检查 | `GET /api/health`，返回 `{ status, version, time }` |
| 部署形态 | 独立 Go 进程，默认 `http://localhost:8080` |

## 2. 接入方式（混合模式）

采用「**数据直连 + 生效通知走网关**」的混合模式：

```
映射数据维护：本系统 ──TypeORM 直连──► MySQL(teyvat_guide 库) 的 asset_* 映射表
生效通知：    本系统 ──网关代理──► http://127.0.0.1:8080/api/admin/assets/reload
服务状态：    本系统 ──网关代理──► http://127.0.0.1:8080/api/health
```

- 两个数据库都在同一 MySQL 实例（`teyvat_admin` / `teyvat_guide`），直连成本低。
- 注册表配置：`code = "teyvat-guide"`，`auth_type = "header-key"`，`auth_config` 存 X-Admin-Key（当前取该项目 `config.yaml` 的 `auth.jwt_secret`）。
- 本系统浏览器侧只携带自身 Session，X-Admin-Key 与数据库连接信息不出服务端。
- 该项目无需配置 CORS。

## 3. 功能模块设计

### 3.1 资产映射管理（M2 · 直连 teyvat_guide 库）

**连接层：**

```
src/lib/teyvat/
├─ db.ts          # 第二个 TypeORM DataSource（teyvat_guide 库），synchronize: false
├─ entities/      # 影子实体：与 Go GORM 模型字段一一对应
│  ├─ TeyvatCharacter.ts   # asset_characters
│  ├─ TeyvatWeapon.ts      # asset_weapons
│  └─ TeyvatRelicSet.ts    # asset_relic_sets
└─ assets.ts      # 业务封装：list / upsert / remove / reloadMemory
```

- 影子实体标注「外部 Schema，归 teyvatGuide AutoMigrate 所有」，**本系统禁止对它做任何迁移**，只读写。
- 独立 env：`TEYVAT_DB_*`（缺省复用同一 host/账号）。
- **实际表名以数据库为准**（无 `asset_` 前缀）：`characters` / `weapons` / `relic_sets` / `missings`（另有 `text_map_entries` / `prop_maps` / `fight_props` / `affixes` / `character_stat_weights` / `player_profile_snapshots`），文档部分章节的 `asset_*` 命名属早期设计，以真实库为准。

**功能模块：**

| 模块 | 表 | 操作 |
| --- | --- | --- |
| 角色管理 | `characters` | 列表（分页/搜索）、新增（id + 名称/元素/星级/图标）、编辑、删除 |
| 角色推荐属性 | `character_stat_weights` | 按 `character_id` 维护 `payload` JSON：副词条（statKey/weight/tier）+ 三件主词条；statKey 选项来自 `prop_maps` |
| **评分权重（并入推荐属性）** | `character_stat_weights`（`payload.score`） | **2026-09-27 合并**：评分权重不再单独成页/成表，写在推荐属性 payload 的 `score` 块里 ✓ —— 角色行「推荐属性」弹窗内即可编辑：小助手口径 **7 维 0~100**（`dims`，key 与推荐词条同批 `FIGHT_PROP_*` ✓）+ 旅行者**按元素形态**各一套（`byElement`，可增/删/切换 ✓）。<br>⚠️ 条件规则（`character_relic_weight_rules`）**不参与算分**（同日决定 ✗）⇒ 不展示、实体已删（库表与种子保留 ✓）<br>写后自动 `reload?purgeSnapshots=true`（复用既有同步链路 ✓）；`character_relic_weights_mp` 表降级为服务端过渡兜底、后台不再读 ✓ |
| 武器管理 | `weapons` | 同上（id / type / rarity） |
| 圣遗物套装管理 | `relic_sets` | 同上（set_id / name / icon） |

**推荐属性 payload 结构**（与 teyvatGuide 一致）：

```jsonc
{
  "subStats": [
    { "statKey": "FIGHT_PROP_ATTACK_PERCENT", "weight": 10, "tier": "primary" },
    { "statKey": "FIGHT_PROP_CRITICAL", "weight": 8, "tier": "secondary" }
  ],
  "mainStats": { "sand": "攻击力", "goblet": "冰元素伤害加成", "circlet": "暴击率" }
}
```

`tier`（primary/secondary）透传到前端着色；修改后同样触发缓存同步（reload + 清快照）。

UI：菜单「AI 提瓦特向导」下新增「资产映射管理」，页内 Tabs 切换三张表；TDesign Table + Dialog 编辑；rarity 用星级 Tag，element 用彩色 Tag。

**缓存同步（关键）：**

teyvatGuide 启动时把映射表全量加载进内存，直改数据库它感知不到，因此每次写操作后：

```
本后台写库成功
  → POST /api/admin/assets/reload?purgeSnapshots=true（服务端刷新内存并一并清空档案快照）
  → 页面提示「已保存并刷新内存，档案快照已清空」
```

- teyvatGuide 管理接口鉴权：请求头 `X-Admin-Key`（本系统取环境变量 `PROJECT_TEYVAT_GUIDE_ADMIN_KEY`）。
- `purgeSnapshots=true` 由服务端负责清空 `player_profile_snapshots`；本系统在 reload 失败时才兜底直删快照表。
- **未送达通知**：reload 失败时写入本系统 `project_notifications` 表（project_code / action / http_status / message / attempts）；「服务状态」页展示未送达列表并提供「重试全部」，重试成功后标记为 `sent`，仍失败则累加尝试次数。

reload 失败不回滚写库（数据已正确，只是内存暂时旧），页面明确提示「已入库，内存刷新失败，请检查 teyvatGuide 是否在线」。

| --- | --- | --- | --- |

| 预设问答维护 | `GET/POST /internal/v1/admin/preset-qa`、`PUT /internal/v1/admin/preset-qa/{id}` | ✅ 已实现（2026-09-14，契约见 `../web/04-API接口文档.md` §7.2） | 运营随时改预设问答（C 端未登录可见的内容），改完即生效 |

## 6. 响应体归一化

teyvatGuide 统一响应 `{ code, message, data }`（`code === 0` 成功），与本系统现有 `success/message` 风格不同，由网关层完成转换：

| teyvatGuide | 网关输出 |
| --- | --- |
| code = 0 | `{ success: true, data }` |
| code = 400 | `{ success: false, message: "参数错误" }` |
| code = 404 | `{ success: false, message: "资源不存在" }` |
| code = 502 / 503 | `{ success: false, message: "上游服务异常，请稍后重试" }` |
| 网络不可达 | `{ success: false, message: "teyvatGuide 服务不可达" }` |

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| Go 侧 `AutoMigrate` 改表结构，影子实体漂移 | 影子实体只映射稳定字段；表结构变更属 teyvatGuide 大版本事件，同步更新影子实体 |
| 主键冲突/误删映射 | 删除走确认弹窗；upsert 语义明确「按 ID 覆盖」 |
| reload 时 Go 服务不在线 | 写库不阻塞，页面提示手动 reload；服务状态面板可查在线状态 |
| 数据库账号权限 | 本系统需要 teyvat_guide 库读写权限；凭证只存服务端 env |
