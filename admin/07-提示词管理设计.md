# 07 · 提示词管理设计（AI 提瓦特向导）

> **用途**：后台「AI 提瓦特向导 → 提示词管理」页的设计与口径。
> **解决的问题**：派蒙人格 / 回答规则**该存哪、由谁改、怎么回滚**——此前唯一的路是手写 SQL。
> **契约真源**：`../shared/03-主服务对接说明.md` §5.2；读取面（AI 服务用）见同文 §5.1。
> **状态**：✅ 已实现（2026-09-15）。

## 1. 背景与目标

| 项 | 说明 |
| --- | --- |
| 现状（2026-09-12 起） | 提示词已入库（`ai_prompts` 表），AI 服务经 `GET /internal/v1/ai/prompts` 按场景拉取；代码里的 `prompts/paimon.json` **只是 file 后端兜底**，不是运行时来源 |
| 痛点 | 改一句话要走 SQL：版本号靠人算、容易误覆盖老版本；运营看不到"线上现在是哪一版" |
| 目标 | ① 可视化：每场景各版本的启用态与「生效中」标记；② 只允许「新增版本 + 启停」——**内容按版本不可变**；③ 回滚只拨一个开关，不需要改内容 |

## 2. 口径（三条，动手前先读）

1. **内容不可变**：没有"编辑某版本内容"的接口。改文案 = **新增一版**（`version` 由服务端分配为当前最大版本 + 1）；
2. **生效 = 启用且版本最高**：新增一版并启用即为生效版本，老版本留着不动；
3. **回滚 = 把新版本 `enabled` 置 0**：自动回落到该场景下一个启用版本。

补充口径：**不做物理删除**；同一场景多版本共存（`uk_scene_version` 保证 `(scene_key, version)` 唯一）；生效延迟 **≤60s**（AI 服务 `PROMPT_STORE_CACHE_TTL=60`），**不需要重启任何服务**。

## 3. 主服务接口（内网 · `X-Internal-Key`）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/internal/v1/admin/ai-prompts` | 全部版本（**含未启用**）+ `servedScenes` 白名单 |
| POST | `/internal/v1/admin/ai-prompts` | 新增一版 `{sceneKey, content, remark?, enabled?}`；`version` 由服务端分配；`enabled` 缺省 true |
| PUT | `/internal/v1/admin/ai-prompts/{id}` | 只接受 `{enabled}`：启用 / 停用（停用生效版本 = 回滚） |

**列表字段**：`id / sceneKey / version / enabled / remark / content / served / effective / createdAt / updatedAt`。

| 标记 | 含义 |
| --- | --- |
| `effective` | 该行就是该场景**当前生效版本**（启用且版本最高） |
| `served` | 该场景**是否会被 AI 服务读取**。`false` = 可以入库（提前准备 / 留档），但当前不生效，页面给「当前不生效」标记，写入时主服务打 warn 日志 |

**校验**：场景键 `^[a-z][a-z0-9_]{0,63}$`；内容非空且 ≤ 20000 字；备注 ≤ 200 字；id 不存在 → **404**；参数不合法 → **400**。

> ⚠️ AI 服务只读 `paimon_base → paimon_rules → paimon_fewshot`（**顺序即拼接顺序**，影响 DeepSeek 前缀缓存）。
> 这份白名单必须与 `ai-service/app/chains/persona.py` 的 `STABLE_SCENES` 保持同步；主服务侧常量在 `internal/service/ai_prompt_admin.go`。

## 4. 后台页面（本系统侧）

```
src/app/admin/teyvat-guide/
├─ PromptPanel.tsx     # 列表 + 新增版本弹窗 + 启停 + 查看全文
└─ prompt-actions.ts   # Server Actions（requireAdmin 兜底）
src/lib/
└─ teyvat-prompts.ts   # 内网客户端（server-only，带 X-Internal-Key）
src/app/admin/AdminShell.tsx  # 菜单「AI 提瓦特向导 → 提示词管理」
```

交互与「预设问答」页同构（降低学习成本）：

| 元素 | 行为 |
| --- | --- |
| 列表 | 按 `场景升序 → 版本倒序`；列：场景（带 `served` 标记）/ 版本（生效中标「生效中」）/ 内容摘要 / 备注 / 状态 Switch / 更新时间 / 操作 |
| 新增版本 | 弹窗：场景键（三个内置场景一键填充）+ 内容（Textarea，minRows 12）+ 备注 + 「保存后立即启用」 |
| 以此新建版本 | 把某行内容复制进弹窗——**改文案的标准姿势** |
| 查看 | 只读弹窗看全文 + 创建 / 更新时间与备注 |
| 状态 Switch | 直接调 PUT；停用生效版本时提示「已回滚到 vN」 |

**不做**：直接编辑某版本内容（违背"不可变"）、物理删除、Diff 对比、拖拽排序。

## 5. 验收清单

- [ ] 列表能看到多版本共存，并正确标出「生效中」（启用且版本最高）
- [ ] 新增版本：版本号 = 上一版 + 1（服务端分配）；启用后 **≤60s** 生效（无需重启）
- [ ] 「保存后立即启用」关掉 → 落成未启用，**不影响线上**（GORM `default:true` 零值陷阱有单测守着）
- [ ] 停用当前生效版本 → 自动回落到上一启用版本；再启用能回到新版
- [ ] 写入 `served=false` 的场景 → 列表标「当前不生效」，主服务日志有 warn
- [ ] 参数校验：场景键非法 / 内容空 / 内容超 20000 字 → 400；不存在的 id → 404
- [ ] 缺少或错误 `X-Internal-Key` → 401；浏览器侧看不到任何密钥
- [ ] 非管理员访问 → 被 `requireAdmin()` 拦回首页
