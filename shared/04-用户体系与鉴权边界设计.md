> 前置阅读：`01-多项目管理平台总体设计.md`、`03-AI派蒙服务运维接入.md`

## 1. 三类角色与信任域

| 角色 | 归属服务器 | 鉴权 | 数据 |
| --- | --- | --- | --- |
| **C 端用户**（原神玩家） | web 服务器（teyvat-guide `:8080`） | 用户 JWT（`Authorization: Bearer`） | `teyvat_guide` 库：users / chat_* / UID 绑定 |
| **后台管理员**（运维人员） | 运维/后台系统（demo-app） | Session/Cookie（`admin_session`） | `demo_project` 库：users（permission_level=0） |
| **服务间调用** | —— | `X-Admin-Key`（管理动作）/ `X-Internal-Key`（内网只读管理）/ `X-AI-Key`（主服务↔AI 服务） | —— |

**结论**：C 端登录由 **web 服务器**唯一负责；后台管理员登录由 **后台系统**独立负责；AI 服务器**不参与任何登录**（规格禁止）。

> 三类鉴权密钥**必须各自独立**，禁止复用。

## 2. 为什么用户中心不放后台

- C 端登录要暴露给公网前端（web 承载），后台不面向 C 端用户；
- 用户身份/会话/UID 绑定/聊天记录都贴着 `teyvat_guide` 库，用户中心内聚在此；
- 后台当用户中心会引入额外故障链路，违背业务/运维解耦；
- AI 服务无状态，不得持有用户数据。

## 3. 后台"管理用户"的方式：内网管理接口（方案 A）

```
浏览器 → 后台 Server Action →（服务端直连，X-Internal-Key）→ web 服务器 /internal/v1/admin/*
```

- 内网接口**只对内网开放**，浏览器与公网都接触不到；
- 密钥 `PROJECT_TEYVAT_GUIDE_INTERNAL_KEY` 只存后台服务端；
- 封禁等写操作在 web 服务器侧执行（可联动会话失效）。

**为什么不对用户用"直连数据库"**：用户是核心实体、写操作带业务规则（封禁需踢会话），直连会绕过校验；直连仅适用于**低风险、读多写少**的资产映射（见 `02`）。

## 4. web 服务器接口契约（teyvat-guide，已实现）

统一信封 `{code, message, data}`，`code === 0` 为成功；鉴权请求头 `X-Internal-Key`；仅内网可达。
`auth.internal_key` 未配置时**该组路由不注册**（安全默认）；请求头缺失/错误一律 401。

### 4.1 用户列表

`GET /internal/v1/admin/users?keyword=&page=1&pageSize=20`

```json
{
  "code": 0, "message": "ok",
  "data": {
    "items": [
      {
        "id": 1, "username": "traveler", "displayName": "旅行者",
        "genshinUid": "100000001", "status": "active",
        "createdAt": "2026-09-01T10:00:00+08:00",
        "lastLoginAt": "2026-09-10T20:00:00+08:00",
        "totalTokens": 123456
      }
    ],
    "total": 42, "page": 1, "pageSize": 20
  }
}
```

- `status`：`active` / `banned`；`genshinUid` / `lastLoginAt` 可为 `null`；
- `keyword` 匹配 用户名 / 昵称 / 游戏 UID；
- `totalTokens`：该用户累计消耗（web 服务器落 `chat_*` 聚合）。

### 4.2 封禁 / 解封

`POST /internal/v1/admin/users/status`

```json
{ "id": 1, "banned": true }
```

→ `{ "code": 0, "message": "ok", "data": null }`

- 服务端需在封禁时使该用户既有会话/JWT 失效；
- 幂等：重复设置同一状态不报错。

### 4.3 错误码

| code | HTTP | 含义 |
| --- | --- | --- |
| 0 | 200 | 成功 |
| 401 | 401 | 缺少/错误的 `X-Internal-Key` |
| 404 | 404 | 用户不存在 |
| 400 | 400 | 参数错误 |

### 5.1 web 侧实现（已完成）

| 层 | 文件 | 说明 |
| --- | --- | --- |
| 路由注册 | `internal/router/router.go` | `/internal/v1/admin` 组；`auth.internal_key` 为空时整组不注册 |
| 鉴权中间件 | `internal/middleware/internal_key.go` | `InternalKeyAuth`，校验 `X-Internal-Key`，独立于 JWT / `X-Admin-Key` |

**封禁联动语义**（`docs/04-API接口文档.md` §7 有完整登记）：`JWTAuth` / `JWTAuthOptional` 每次请求都经 `middleware.UserStatusChecker(userAdminSvc.IsBanned)` 校验 → **封禁后既有 JWT 立即失效**，且无法重新登录；解封后恢复。

## 7. 安全基线

- 内网接口**不暴露公网**，仅内网可达；
- `X-Internal-Key` 独立生成，禁止复用用户 JWT / `X-Admin-Key` / `X-AI-Key`；
- 后台管理员账号与 C 端账号**不同表、不同鉴权**，后台不可用 C 端账号登录；
- 封禁等写操作在 web 侧执行并联动会话失效。
