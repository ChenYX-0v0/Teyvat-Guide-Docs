# 05 · 密钥与凭据管理

> 状态：**已落地**（2026-09-19 首次全仓扫描通过 + 清单成文；配套工具 `deploy/check-secrets.ps1`）
> 前置阅读：`04-用户体系与鉴权边界设计.md`（三类鉴权密钥必须各自独立）、`../ai/06-阿里云部署方案.md`（云上密钥从哪来）
> **本文只写"位置、用法、轮换步骤"，不写任何值。**

---

## 1. 四条原则

1. **一个密钥只存一处**，其他位置"引用同一个值"，绝不复制成"第二份真相"。改的时候按 §2 的「联动」列改齐。
2. **值不进仓、不进对话、不进镜像**：`.gitignore` 已覆盖 `server/config/config.yaml`、`.env` / `.env.*`、`demo-app/.env.local`、`deploy/out/`；容器只从 `env_file` 注入，`server/Dockerfile` 不 COPY `config/`。
3. **应用永远不用高权限账号**：业务服务只拿 `teyvat`（权限仅 `teyvat_guide.*`），后台只拿 `teyvat_ops`（权限仅 `teyvat_admin.*`）。高权限账号（建库/授权）**只用于人工运维**，不进任何配置文件。
4. **每条密钥都要有轮换办法**：§4 逐条写了"换它要动哪几处、怎么验证"。

> **与文档仓 `README §约定 6`（本地调试密钥例外条款）的关系**：AI 联调时**可以直接读本机的密钥文件**
> （`.env`、`config/config.yaml`、凭据文件），**不需要你把密钥值粘贴到对话里**——让 AI 自己从文件读、
> 输出里做遮蔽即可（2026-09-19 迁移 RDS 就是这么做的：密码只落在 `deploy/out/rds-credentials.txt`，
> AI 从文件读取，输出只用"长度 24"这种信息）。
> **反例**：那次把 RDS 账号名与密码发进了对话——**值一旦进对话就等于进日志**，按 §5 处理。

## 2. 清单（值另存，见"云上唯一来源"列）

| 密钥 | 用途 | 云上唯一来源 | 本地开发处 | 联动（换它要连着改） |
| --- | --- | --- | --- | --- |
| RDS `teyvat` 密码 | 主服务连业务库 | 根 `.env` → `TEYVAT_DATABASE_PASSWORD` | `server/config/config.yaml` | 重启主服务 |
| RDS `teyvat_ops` 密码 | 后台连管理库 | `demo-app/.env.local` → `DB_PASSWORD` | 同左 | 重启后台 |
| `AI_SERVICE_KEY` | 主服务 ↔ AI 服务；后台探测 AI | 根 `.env` **与** `ai-service/.env`（**必须同值**） | 同名 | ⚠️ **三处**：主服务 + AI 服务 + 后台 `PROJECT_TEYVAT_AI_ADMIN_KEY` |
| `TEYVAT_AUTH_JWT_SECRET` | C 端用户登录 token | 根 `.env` | `server/config/config.yaml` | 换完全体用户需重新登录 |
| `TEYVAT_AUTH_ADMIN_KEY` | 后台 → 主服务管理接口（资产 reload 等） | 根 `.env` | `server/config/config.yaml` | ⚠️ 后台 `PROJECT_TEYVAT_GUIDE_ADMIN_KEY` 必须一致，否则提示「内存刷新被拒绝（凭证无效）」 |
| `TEYVAT_AUTH_INTERNAL_KEY` | 后台 → 主服务内网接口（用户管理）**＋ AI 服务拉提示词** | 根 `.env` | `server/config/config.yaml` | ⚠️ **两处**：后台 `PROJECT_TEYVAT_GUIDE_INTERNAL_KEY` **与** `ai-service/.env` 的 `PROMPT_STORE_KEY`（提示词走 `http` 时用它做 `X-Internal-Key`；不同值 → 容器里拉不到提示词，**静默降级**为文件兜底，日志不明显） |
| `TEYVAT_AUTH_SEED_PASS` | 首次启动的种子账号密码 | 根 `.env` | —— | 建号后建议改密，并把该变量留空 |
| `DEEPSEEK_API_KEY` | AI 服务调用模型（付费） | `ai-service/.env` | 同左 | 重启 AI 服务；**节制使用**（约定 6） |
| `SMS_CODE_HMAC_SECRET` | 短信验证码 HMAC | `demo-app/.env.local` | 同左 | 换掉会让在途验证码失效（可接受） |
| RDS 高权限账号 | **仅人工**建库 / 建账号 / 授权 | **只在阿里云控制台 + 密码管理器** | —— | **不入任何文件**，用完即走 |
| ACR 镜像仓凭据 | `docker login` 拉私有镜像 | ECS 上 `~/.docker/config.json`（600） | —— | `docker logout` 可随时清理。**现状（2026-09-20）**：首部署时 ECS **尚未**登录，用 `docker save` → `scp` → `docker load` 传入（三个 tar 共 109MB）；**想改用 `docker compose pull` 前，需先在 ECS 上 `docker login` 一次** |

## 3. 运行时是怎么被加载的（决定密钥该放哪）

| 服务 | 加载方式 | 注意 |
| --- | --- | --- |
| 主服务（Go） | viper 读 `config.yaml` + **进程环境变量 `TEYVAT_*` 覆盖**（点号换下划线） | ⚠️ **viper 不读 `.env` 文件**：本地改 `config.yaml`，容器里靠 compose 注入。⚠️ **viper 的 `Unmarshal` 只回填"已知键"**（config 里出现过的、或 `SetDefault` 注册过的）→ **新增配置项时必须同步在 `setDefaults()` 补一行**，否则容器里（无 `config.yaml`）该环境变量**静默失效**（2026-09-20 踩到两例：`ai.api_key` 漏注册 → 调 AI 服务 401「缺少 X-AI-Key」；`ai.model` 遗留模板默认 `gpt-4o-mini` → 上游 DeepSeek 400） |
| AI 服务（Python） | 自身 `ai-service/.env`（compose 的 `env_file` 也指向它） | 密钥只在这一个文件里 |
| 后台（Next.js） | `demo-app/.env.local`：`DB_*` = 管理库、`TEYVAT_DB_*` = 业务库 | ⚠️ 两套连接别只改一套；`TEYVAT_DB_NAME` **不会**回落到 `DB_*` |
| compose | 根 `.env` 插值 + `:?` 强制必填（缺了直接起不来，刻意的） | ⚠️ `docker compose config` 会把明文展开，**别把输出外发** |

## 4. 各环境怎么放

| 环境 | 做法 |
| --- | --- |
| **本地开发**（Windows） | `server/config/config.yaml`（已 gitignore）、`demo-app/.env.local`、`ai-service/.env`。允许直连云端 RDS 的外网地址用于联调 |
| **云上 ECS** | `/opt/teyvat-guide/.env`，**权限 600、属主=部署用户、目录 700**；不进镜像、不进 git。`ai-service/.env` 同理 |

## 5. 轮换手册

**先看规则**：换密钥只在新旧值都可用时"平滑"；本项目的密钥大多是"要么全对要么全错"，所以流程是**改文件 → 重启 → 验证**。

| 要换的 | 步骤 | 验证 |
| --- | --- | --- |
| RDS `teyvat` / `teyvat_ops` | ① 控制台 → 账号管理 → 重置密码；② 更新对应配置（主服务 `config.yaml` 或后台 `.env.local`）；③ 重启对应服务 | `curl /api/health`；后台登录一次；看日志有无 `Access denied` |
| 主服务三把 key（JWT / Admin / Internal） | ① 重新生成（`python -c "import secrets;print(secrets.token_urlsafe(48))"`，**三把各自独立**）；② 云上改根 `.env`；③ **同时**改后台 `.env.local` 里对应的 `PROJECT_*`；④ 重启主服务与后台 | 后台「资产映射管理」改一条数据 → 提示应为"已保存并刷新内存"（不是"凭证无效"）；C 端重新登录成功 |
| `AI_SERVICE_KEY` | ① 生成新值；② 改根 `.env` **与** `ai-service/.env`（同值）；③ 改后台 `PROJECT_TEYVAT_AI_ADMIN_KEY`；④ 重启 AI 服务 + 主服务 + 后台 | C 端问一句能正常回答；后台「提示词管理」能读到版本 |
| `DEEPSEEK_API_KEY` | ① 服务商控制台新建 Key（**先别删旧 Key**）；② 改 `ai-service/.env`；③ 重启 AI 服务；④ 验证通过后再删旧 Key | 问一句能收到回答；看 AI 服务日志无 401 |
| `SMS_CODE_HMAC_SECRET` | 改 `demo-app/.env.local` → 重启后台 | 发一条验证码 → 能收到并校验通过（在途的会失效） |
| RDS 高权限账号 | 控制台重置即可（应用不使用它，**零影响**） | 用新密码做一次 `SHOW DATABASES` |

**触发条件**：① 值曾出现在对话/截图/工单/临时文件；② 人员变动；③ 定期（个人项目 **6~12 个月**一次）。

**2026-09-19 的待轮换清单与进展**：
① **RDS 高权限账号（值曾发进对话）—— ⬜ 仍未在控制台重置，待办**（应用不使用它，重置零影响）；
② ✅ **已完成（2026-09-20）**：云端三把 key（JWT / Admin / Internal）+ `AI_SERVICE_KEY` + seed 口令**全部重新生成**，并一次同步**五处**（根 `.env`、`config.yaml`、`ai-service/.env`、`demo-app/.env.local` 的三把 `PROJECT_*`）+ AI 服务 `PROMPT_STORE_KEY`，复核 7 处耦合全一致；
③ `DEEPSEEK_API_KEY` —— 未动（未发现外发）。

## 6. 泄露应急（发现某把 key 外泄）

1. **先换后查**：按 §5 立刻重置/轮换（别先花时间查日志）；
2. **收口**：若是库密码，检查 `mysql.user` 里有没有多出来的账号、`SHOW PROCESSLIST` 有无异常连接；若是 API Key，到服务商控制台看用量异常；
3. **清痕**：删掉含真值的临时文件（`deploy/out/` 里的凭据、导出的 dump、截图）；
4. **补防呆**：把这次的真值加进 `deploy/out/known-secrets.txt`（本机、已 gitignore），下次扫描能精确命中；
5. **记录**：在下方「变更记录」写一行（日期 + 换了哪把 + 原因），别写值。

## 7. 防呆与审计

| 动作 | 命令 |
| --- | --- |
| 提交前扫描（暂存区） | `powershell -ExecutionPolicy Bypass -File .\deploy\check-secrets.ps1` |
| 全量扫描（跟踪文件） | `... -File .\deploy\check-secrets.ps1 -All` |
| 查某把已知密钥是否入过库（全历史） | `git log --all --oneline -S "<粘贴那把的值>"`（无输出 = 干净） |
| 查敏感文件是否曾入库 | `git log --all --name-only --diff-filter=A -- '.env*' 'server/config/config.yaml' 'deploy/out/*'` |
| 想让扫描自动跑在提交前 | 自己加 `.githooks/pre-commit` 并 `git config core.hooksPath .githooks`（**改 git 配置属你的决定，工具不代劳**） |

**2026-09-19 首次扫描结论（四仓：主仓 / admin / ai / docs）**：

- 三条在用密钥在**被跟踪文件**与**全历史**中均 **0 命中**；
- RDS 密码 **0 命中**；`config.yaml` 与 `.env` **从未入库**（只有 `.env.example`）；
- 文档仓无"像真值"的内容；
- 三仓无 `secret|api_key|password = <长串>` 的可疑赋值。

## 8. 升级路径（什么时候不该再用文件）

| 阶段 | 方案 | 触发条件 |
| --- | --- | --- |
| **现在**（单机、一两个运维） | `.env` 文件 + 600 权限 + gitignore + `check-secrets.ps1` | 够用，别过度设计 |
| 多人协作 / 多环境（测试+生产）/ 有外部运维 | **阿里云 KMS 凭据管家（Secrets Manager）** 或 **私有 OSS 桶 + KMS 加密**，ECS 用 **RAM 角色**免 AK 拉取，启动脚本注入环境变量 | 出现"谁都能看 `.env`"或"要轮换但不敢停机" |
| 有合规要求 / 出过事故 | 上一行 + 强制轮换策略 + 访问审计（ActionTrail） | 到那个量级再说 |

## 9. 反模式（别做）

- 把密钥写进代码、文档、README、测试用例、错误信息、日志；
- 同一把 key 跨无关服务复用（**唯一的例外**是 `AI_SERVICE_KEY`：它本身就是"主服务 ↔ AI 服务"的共享密钥，两侧必须同值）；
- 给应用账号授高权限，或让应用连 `mysql` 库；
- 把 `deploy/out/` 的 dump / 凭据文件经网盘、群、邮件传（用 `scp`；dump 里含全部业务数据与 bcrypt 密码哈希）；
- `docker compose config` 的输出贴到任何地方（明文展开）；
- 在对话 / 截图 / 工单里贴真值——**要让 AI 用，就让它自己读文件**（约定 6）。
