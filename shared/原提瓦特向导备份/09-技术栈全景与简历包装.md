## 1. 项目是什么

**提瓦特向导**：面向《原神》玩家的 AI 问答与账号分析产品 —— 玩家绑定游戏 UID 后，AI（人格「派蒙」）可以结合**实时角色档案**（Enka 公开数据）回答配队 / 毕业线 / 天赋顺序 / 圣遗物评分 / 终局玩法进度，并给出**可追溯**的结论。

| 维度 | 事实 |
| --- | --- |
| 角色 | **独立完成**：需求 → 设计 → 前后端 → AI 侧 → 部署 → 备案上线（个人项目） |
| 规模 | **4 个代码仓 + 1 个文档仓**；主服务 **25 张表**、**36+ 接口**；前端 **18 个埋点事件** |
| 上线 | 已部署阿里云（ECS ＋ RDS MySQL），**ICP 备案已通过**，HTTPS 已启用（2026-09-27 起） |
| 迭代 | prompt 迭代到 **v21**；生产镜像 **18+ 个 tag**（`YYYYMMDD-HHMM`），旧 tag 可一键回滚 |

## 2. 四仓拓扑

| 仓 | 技术 | 职责 | 部署形态 |
| --- | --- | --- | --- |

**值得写进简历的前端实现**：

1. **SSE 流式渲染**：乐观插入 `pending` 占位 → `fetch` + `ReadableStream` 逐行解析 → 事件序 `session → delta* → (done|error)`；`done` 带 `sessionId/tokens/elapsedMs`；**中断保留已产出内容** ✓
2. **移动端 8 条硬规范**：`h-dvh` 替代 `100vh`、`pb-[max(1rem,env(safe-area-inset-bottom))]`、输入框 **≥16px** 防 iOS 聚焦放大、抽屉不放进 `backdrop-blur/transform` 祖先（会破 `fixed`）、导航**唯一来源** `navItems.ts`（桌面侧栏与移动抽屉共用）✓
3. **分页策略分级**：会话列表页码分页（`page/pageSize`）；消息明细**向上游标分页**（`beforeId`，默认 100 / 上限 200）；后台用 `afterId` ✓

### 3.3 AI 服务（Python，无状态）

| 层 | 选型 | 备注 |
| --- | --- | --- |
| 语言 | **Python 3.11+** | 开发机实测 3.14.3 |
| Web | **FastAPI ＋ uvicorn[standard]** | |
| LLM 编排 | **LangChain v1 线**：`langchain-core 1.6.x` ＋ `langchain-openai 1.6.x` | 用 `ChatOpenAI` 指向 `api.deepseek.com`；**不用 `langchain-deepseek`** |
| 模型 | **deepseek-flash**（单模型） | 四档 profile：`chat`(temp .85/1024)、`analysis`(thinking high/4096)、`tool`(.2/2048)、`json`(.1/2048) |
| 校验 / 配置 | pydantic ＋ pydantic-settings | |
| 日志 | **structlog**（JSON） | |
| HTTP | httpx | |

**核心设计（这是"AI 应用工程"最值钱的部分）**：

1. **无状态硬约束**：不建用户体系、不写 `chat_*`、不直连 MySQL；会话持久化归主服务 ⇒ **可以水平扩容、重启零影响** ✓
2. **零工具**：`app/` 里**没有** LangGraph、没有 `bind_tools` ⇒ 从架构上杜绝"模型自己调工具越界"（`ai/09 §1`）✓
3. **prompt 四段式 ＋ 稳定前缀**：`paimon_base`（身份）→ `paimon_rules`（规则/边界）→ `paimon_fewshot`（语气）→ `request_system` → 动态段（档案/资产/检索）；**稳定前缀保证 DeepSeek 前缀缓存命中** ✓
4. **提示词版本化**：`ai_prompts` 表 `scene_key + version + enabled`，内容不可变、**生效 = 最高启用版本**、**回滚 = 置 0**、**≤60s 热生效**（内存 TTL 60s）⇒ 改人格不用发版 ✓
5. **上下文契约**：`context.player / goal / summary`，AI 侧 `extra="allow"` ⇒ **加字段不炸老版本** ✓
6. **超时纪律**：上游 **55s / 重试 ≤1**；主服务超时必须 **65s（>55s）**；**禁止"长超时 + 多次重试"叠加**，4xx 不重试 ✓
7. **告警**：进程内 5 条规则（提示词回退 / 存储 HTTP 失败 / 5xx 突增 / 上游 5xx 比例 / 缓存退化），窗口 300s、评估 30s、冷却 1800s，通道 = 日志 ＋ webhook ＋ `/metrics` ✓
8. **分类器**：`AI_CLASSIFY_MODE=off|sample`，`game/chitchat/other_domain/injection/emotion...`，**`NULL` = 未判定 ≠ false** ✓

## 4. 六个可以当"架构决策"讲的点

| # | 决策 | 为什么这么定 | 代价（面试官会问）|
| --- | --- | --- | --- |
| 1 | **AI 服务无状态、零工具** | 安全边界：拿不到 DB 与 Token，模型无法越权；扩容/重启零成本 | 能力受限（不能做多步检索）；替代方案是把编排放在主服务 |
| 2 | **提示词进库、多版本、置 0 回滚** | 人格与规则迭代极频繁（**已 v21**），走代码发布太重 | 需要一致性校验：库里版本与代码默认值要能回退 |
| 3 | **上下文预算硬截断** | token 成本与延迟的**唯一可控点**；超预算**整条丢弃**而非截半条 | 信息可能缺失 ⇒ 必须显式告知"其余 N 个已省略" |
| 4 | **结构化事实卡替代长文语料** | 模型只会"照背结论"⇒ 换成 `provides/shreds/cannot/needs` 让模型**推理**，并每条带原文出处 | 抽取成本（120 张卡、3000+ 条事实），且需要"结论必须能从 facts 推出"的护栏 |
| 5 | **四类密钥彼此隔离 + 网关注入** | 单一密钥泄露不牵连全局；后台不接触业务库密码 | 运维复杂度上升（轮换、扫描）|
| 6 | **门禁而非流程** | 一天内连续三次"新改动伤旧功能"⇒ 把验收**固化成脚本**（preflight ＋ golden 断言）| 每次提交多花几十秒 |

## 6. 简历怎么写

### 6.1 三条原则

1. **每条都要有"结果或数字"** —— "实现了 AI 问答"没人看，"把回答延迟压到 1.46s、上下文预算 1500 token 硬截断"才有信息量；
2. **写"决策与代价"，不写"用了什么库"** —— 面试官不关心你用了 Zustand，关心你为什么不用 Redux / 为什么不拆微服务；
3. **给面试官留钩子** —— 主动写一句你最想被问的（例如"因一次数据事故建立回归门禁"），然后把故事备在 §6.3。

### 6.2 项目条目（可直接改用）

**精简版（3 行，适合一页简历）**：

> **提瓦特向导** ｜ 独立开发 ｜ React 19 · Go · Python(FastAPI) · MySQL · Docker · 阿里云
> - 面向《原神》玩家的 AI 问答与账号分析产品：绑定游戏 UID 后，AI 结合实时角色档案回答配队 / 毕业线 / 圣遗物评分，**已上线并完成 ICP 备案**。
> - 独立完成四仓（C 端 / 主服务 / AI 服务 / 后台）设计开发与部署；主服务 **25 张表、36+ 接口**，前端 **18 个埋点事件**，prompt 迭代 **21 版**。
> - 设计 SSE 流式问答链路与上下文预算机制，首轮响应 **1.46s**（缓存命中 512 tokens）；建立 `preflight` 门禁与 golden 发版断言。

**详版（适合项目经历展开，4~6 条 bullet）**：

> - **端到端交付**：独立完成需求 → 架构 → 前后端 → AI 服务 → 容器化部署 → 备案上线（阿里云 ECS + RDS MySQL 8.0，Nginx 终结 TLS，Compose 三容器），累计 **18+ 生产版本**、旧 tag 一键回滚。

> - **安全与合规**：分层防注入 L0~L5（输入归一 16 例、命中即短路**不调模型**）；四类密钥隔离、网关层隐藏管理接口；用户须知版本化强制确认 + AI 生成内容标识；`robots`/`X-Robots-Tag` 全站 noindex。

| # | 场景（S/T） | 动作（A） | 结果（R） | 会被追问 |
| --- | --- | --- | --- | --- |
| 1 | **从代码到上线**：功能做完了但只有内网 IP，无法合法对外 | 域名（国内注册商）→ ICP 备案 → HTTPS（certbot）→ noindex 三处开关 → 发版/回滚脚本 | **7 天内完成备案并上线**；每次发版留 `.env.bak-<tag>` | 备案卡在哪？HTTPS 怎么续期？回滚验证过吗 |
| 2 | **流式回答"像卡住"** | 定位到 Nginx 缓冲 → 关 `proxy_buffering`、`proxy_read_timeout 120s`；前端改用 `fetch` 流式解析（axios 不行）；定义 `session/delta/done/error` 四类帧，中断保留已产出内容 | 首字可见、`elapsedMs≈1.6s`；断流不再白屏 | SSE 与 WebSocket 怎么选？断线重连呢 |
| 3 | **一天三次"新改动伤旧功能"**（词条同名让面板少一行、残留枚举行让冰伤显示 0.0%、CRLF 让远端脚本报错） | 建 `preflight.ps1`（快档/全档）＋ 种子数据不变式测试（枚举唯一、不许两条都有枚举）＋ 发版 golden 断言（固定 UID 12/12 面板行、丝柯克 61.6%） | 同类事故未再发生；验收从"人眼"变成"脚本退出码" | 为什么不接 CI？golden 断言怎么选 |
| 4 | **模型编出根本不存在的反应名**（按"月感电"对称性造了"月超导"，还说得有理有据） | 不靠"加一句别编造"；把资料结构化（机制卡 facts）＋ 提示词改为"反应名只照数据块写、不许按对称性拼"，且**不专门强调"没有 XX"**（避免把错名词种进用户脑子） | 幻觉类问题从"靠人读回复"变成"数据可推导 + 可评测（机制 30/30）" | 怎么保证模型不绕过 facts |
| 5 | **匿名用户刷 AI 成本** | 匿名禁用 AI 改预设问答；强制登录 + 日配额 100 万 tokens + 并发 ≤2 + 20 次/分；命中注入特征**零 token 短路**；四类密钥隔离 | 成本可控、滥用可观测（18 个埋点）| 配额为什么是软上限？怎么防多账号 |

### 6.5 诚实红线（这几句**绝对不能写**）✗

| ❌ 不能写 | 真实情况 |

| "全链路监控（Prometheus + Grafana）" | 只有 `/metrics` 端点与 5 条日志/webhook 告警 |
| "PWA / 离线可用" | 未做（`web/06`）|
| "生成式 AI 备案已完成" | **ICP 备案**已完成；**生成式 AI 登记未启动**（正在推进）|

### 6.6 高频追问（提前准备）

1. 为什么 AI 服务要无状态？→ 权限边界 + 可扩容 + 重启零影响（§4-1）
2. 为什么不用 LangGraph / 不给模型工具？→ 工具 = 能力质变，注入面变大；宁可让主服务编排（§3.3-2）
3. 为什么提示词进库而不是 git？→ 迭代频率（v21）＋ 热生效 ＋ 置 0 回滚
4. token 成本怎么算的？→ 预算是硬截断点、缓存命中（512/778）、四档 profile
5. 怎么防止模型编造？→ 结构化 facts + "只照数据块写" + 评测集回归；**不是靠一句"别编造"**
6. 25 张表怎么设计的？→ 按职责分：用户 / 会话 / 资产映射 / 攻略机制 / 快照与累积池 / 观测统计
7. 为什么不做微服务？→ 单机单用户量级，拆分只增运维成本；边界靠**进程与权限**而不是网络
8. 怎么保证重构不改行为？→ 行为等价验收（12/12 角色分数零变化、122 角色改动后分数不变）
9. 线上出问题怎么定位？→ 结构化日志 + 请求 ID + 告警规则 + `docker logs` + golden 断言比对
10. 如果重做，会改什么？→ 先接 CI 与前端测试；把期次/时效内容做成表（`ai/12`）；RAG 只在评测证明有收益后上
