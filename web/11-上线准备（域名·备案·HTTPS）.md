# 11 · 上线准备（域名 · 备案 · HTTPS）

> **用途**：把项目从「本机 / 局域网能访问」推到「有正式域名、公网可访问、能对外运营」的实操清单。
> **前提**：服务器在中国大陆 —— 本项目按 `../ai/06-阿里云部署方案.md` 选**阿里云 ECS · 上海地域（cn-shanghai）**（主服务与 AI 服务同机）。
> **现状（2026-09-20）**：ECS 已购并**部署完成**（三容器 healthy、IP 直连回环验收通过），详见 `../ai/06-阿里云部署方案.md §1.1 部署现状`。
> **一句话结论**：大陆服务器对外 → **必须 ICP 备案**；备案需要「**已实名的域名 + 已购买的大陆服务器**」两个条件同时具备；
> 而**开发与备案可以并行** —— 备案期间照常写代码、用 IP/局域网联调，只是**不能把正式域名解析到大陆机器对外提供服务**。

## 1. 顺序与耗时（关键路径）

| # | 步骤 | 在哪做 | 耗时 | 备注 |
| --- | --- | --- | --- | --- |
| 1 | 选名 + **买域名** + 完成**实名认证** | 阿里云（推荐） | 实名 1~3 天 | 域名必须在**国内注册商**，见 §2 |
| 2 | ✅ **买 ECS**（**上海**，包年包月） | 阿里云 | **已完成（2026-09-20）** | 备案要求实例有**剩余时长**（以控制台提示为准）。⚠️ **服务器地域与备案管局无关**，别为备案改地域 |
| 3 | 提交 **ICP 备案** → 阿里云初审 → 管局审核 | 阿里云备案控制台 | 初审 1~2 工作日 + **管局 1~3 周**（各省不同） | **关键路径，越早越好**；期间要回短信核验 |
| 4 | 域名解析 + **HTTPS** + Nginx 反代 → 正式对外 | ECS | 半天 | 见 §5 |
| 5 | **生成式 AI 应用侧合规**（与 ICP 无关，但可能更慢） | 属地省级网信办等 | 不确定 | **并行启动**，见 §7 |

> 完整时间感：**尽早在第 1、2 步动手并提交备案**，第 3 步是纯等待；第 4 步一天内能做完。
> 这期间第 5 步并行推进 —— 否则会出现"网站备案通过了，AI 功能还不能公开提供"的落差。

## 2. 步骤 1：选域名并注册

**注册商必须是工信部批准的国内注册商**（阿里云 / 腾讯云等）：在 Namecheap、Cloudflare、GoDaddy 注册的域名**在国内无法备案**（要么另买、要么先转入国内注册商）。→ **直接在阿里云买**，与 ECS、备案同账号，材料一致性最好。

`.com` vs `.cn`（技术能力完全一样，差别在管谁、要什么材料、好不好买）：

| 维度 | `.com` | `.cn` |
| --- | --- | --- |
| 管理机构 | Verisign（ICANN 认证 gTLD） | CNNIC（国家顶级域） |
| 实名 | 国内注册商同样要求 | **强制实名**，未通过会暂停解析 / 注销 |
| 好名字 | 常用词基本被抢注，常需二手购买 | 明显更容易拿到 |
| 价格 | 首年 ~60-90 元，**续费 ~90-100 元/年** | 常见 30-40 元/年（看续费价，别只看首年） |
| 转移 | ICANN 标准流程，较自由 | 需转移密码，部分注册商另有约束 |

**建议**：`.com` 为主（认知度、迁移自由），**`.cn` 一起注册**做防御（防止别人蹭品牌），另一个后缀 301 跳主域。
域名所有者 = 后续备案主体，**先想好用个人还是公司名义**，别中途过户。

## 3. 步骤 2：买服务器（备案的另一个必要条件）

- 地域：**上海（cn-shanghai）** —— 与 `ai/06`、ACR、RDS **同地域**（同地域才能内网互通、拉镜像快；**2026-09-20 已购**）；
- 计费：**包年包月**（备案对实例剩余时长有要求，按量付费一般不行）；
- **备案服务号**：提交备案时要用，在 ECS 控制台申请（一台实例可申请多个）；
- 带宽：装 1~5 Mbps 只够"出网调 API"；**对外提供网站要另加带宽或上 CDN**（静态资源走 CDN，省钱且更快）；
- 安全组按 `ai/06` §2.2：**不放行 8090**（AI 服务只走 `127.0.0.1`）、**不放行 8080 给公网**（只让本机 Nginx 走回环访问）、SSH 只放行你自己的固定 IP。

## 4. 步骤 3：提交 ICP 备案

**材料**：主体证件（身份证 / 营业执照）、法人 / 网站负责人信息、域名（已实名）、服务器（备案服务号）、**网站服务内容说明**。
个人备案只适合非商业的个人项目；**一旦收费、挂广告、做商业运营，通常需要企业主体**（可能还涉及经营性 ICP 许可，那是另一个证）。

**流程与要点**：

1. 阿里云备案控制台填报 → 阿里云**初审**（1~2 工作日，会打电话核对）；
2. 初审通过 → 提交**属地管局**（**按备案主体所在地**：个人备案 = 身份证所在省；**与服务器地域无关** —— 本项目服务器在上海，但管局按你的主体所在省，最终**以阿里云备案控制台显示的管局为准**）；
3. 期间配合核验：**阿里云 App 人脸核验** + **工信部短信核验**（必须按时回复，超时会退回重来）；
4. 管局审核 **1~3 周** → 通过后拿到备案号。

**备案期间不要做的事**：把正式域名解析到大陆 ECS 对外提供服务 —— 未备案的域名解析到大陆机器会被拦截，站点打不开，还可能影响审核。开发联调继续用 **IP + 端口 / 局域网 / hosts**。
备案通过后：网站底部展示备案号并链接 `https://beian.miit.gov.cn`（这是要求）。

## 5. 步骤 4：解析 + HTTPS + 反向代理

1. **解析**：阿里云云解析加 `A` 记录到 ECS 公网 IP（建议同时加 `www`）；
2. **证书**：阿里云免费 DV 证书（或 Let's Encrypt），装到 Nginx，**配自动续期**（certbot timer / 阿里云证书托管）；
3. **Nginx 反代**（推荐**同域**：页面与 `/api` 同一个域名，前端零改动、**不需要配 CORS**）：

```nginx
server {
    listen 443 ssl http2;
    server_name teyvat.example.com;

    ssl_certificate     /etc/nginx/ssl/teyvat.example.com.pem;
    ssl_certificate_key /etc/nginx/ssl/teyvat.example.com.key;

    # C 端静态资源（web 构建产物）
    root /var/www/teyvat-web;
    client_max_body_size 1m;

    location / {
        try_files $uri $uri/ /index.html;   # SPA 前端路由
    }

    # 主服务 API（8080 只在本机，安全组不放行公网）
    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # ⚠️ 流式对话（SSE）必须关缓冲，否则 delta 会被攒起来一次性下发，
        #    前端的"逐字打字"效果直接坏掉
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}

server {
    listen 80;
    server_name teyvat.example.com;
    return 301 https://$host$request_uri;
}
```

4. **后台（demo-app）不要挂公网域名** —— 内网 / VPN / 至少 IP 白名单 + 独立子域（如 `admin-xxx.example.com` 只对你的 IP 开放）；
5. **前端配置改动点**：C 端本来就走相对路径 `/api`（Vite 代理），同域方案下**代码不用改**；若坚持分离域名（`api.example.com`），则要改前端 baseURL 并同步主服务 CORS 白名单（`router.go` 现只允许本地来源）。

**验收命令**：

```bash
nslookup teyvat.example.com                                   # 解析生效
curl -sI https://teyvat.example.com | head -3                  # HTTPS 200
echo | openssl s_client -connect teyvat.example.com:443 \
  -servername teyvat.example.com 2>/dev/null | openssl x509 -noout -dates   # 证书有效期
curl -s https://teyvat.example.com/api/health                   # 反代到主服务，统一信封
curl -N -X POST https://teyvat.example.com/api/chat \
  -H 'Authorization: Bearer <token>' -H 'Content-Type: application/json' \
  -d '{"message":"你好","stream":true}'                          # 流式应逐段输出，不是最后一次性刷出
curl -m 5 http://<ECS公网IP>:8090/health                        # 预期超时/拒绝（AI 服务不对外）
```

## 7. 生成式 AI 服务的合规（与 ICP 备案是两条线）

`ai/04` / `ai/06` 写的是"服务怎么部署"，**没写"能不能公开提供"** —— 这块是**应用侧合规**，会**影响上线时间**，且办理周期可能**比 ICP 备案更长**，所以要并行推进。

### 7.1 依据（读原文，别看二手转述）

| 规章 | 与本项目的关系 | 施行 |
| --- | --- | --- |
| 《生成式人工智能服务管理暂行办法》 | 面向公众提供生成式 AI 服务：备案、生成内容标识、内容安全、投诉渠道等 | 2023-08-15 |
| 《互联网信息服务深度合成管理规定》 | 生成 / 合成类服务的标识与备案义务 | 2023-01-10 |
| 《互联网信息服务算法推荐管理规定》 | 算法备案（推荐 / 生成类算法） | 2022-03-01 |
| 《具有舆论属性或社会动员能力的互联网信息服务安全评估规定》 | 一旦有用户发帖 / 评论 / 公开内容分发，可能另需安全评估 | 2018-11 |

### 7.2 在哪查 / 找谁（按这个顺序）

**最实用的入口是网信办的定期公告**：国家网信办在 `www.cac.gov.cn` 发布《关于发布生成式人工智能服务已备案信息的公告》
（"网信中国"公众号同步），里面既有**已备案**名单、也有**已完成登记**名单 —— 看同行是怎么归类的，就能判断自己该走哪条。
（最近一期：2026-09-14 公告，7~8 月新增备案 124 款、登记 133 款；截至 2026-08-31 累计备案 1112 款、登记 731 款。）

1. **国家网信办官网**（`www.cac.gov.cn`）：规章原文 + **备案 / 登记信息公告**（先翻这类公告）；
2. **属地省级网信办**（← **你这类应用的受理方**）：官方口径是「**通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能，由地方网信办开展登记**」。
   按**主体属地**（公司注册地 / 实际运营地）受理，**各省口径与材料不完全一样 → 以属地答复为准**。
   建议**先打电话确认**，或在属地政务服务网搜「生成式人工智能服务登记」办事指南；
3. **互联网信息服务算法备案系统**：算法备案（推荐 / 生成类算法）的填报入口与已备案清单查询，入口链接以网信办官网为准；
4. **确认基础模型的备案状态**：查公告名单里 DeepSeek / 通义（百炼）是否已备案，并记下**备案号**（应用侧登记常要填）；
5. **云厂商合规支持**：阿里云 / 百炼的工单与 AI 合规文档 —— 能直接回答"你这种调用方式要不要登记、怎么登记"，实践中是拿到答案最快的路径之一。

### 7.3 备案 vs 登记（判断自己属于哪类）

| 情形 | 走哪条 | 谁受理 | 周期量级 |
| --- | --- | --- | --- |
| 自研 / 微调模型并对外提供 | **大模型备案** | 国家网信办 | 材料重（安全评估、语料与标注说明、模型测评），常见**数月**量级 |
| **调用已备案的第三方模型做应用 / 功能**（← **本项目**：DeepSeek API + 百炼 Embedding） | **登记**（官方口径：「通过 API 接口或其他方式直接调用已备案模型能力的生成式人工智能应用或功能，由**地方网信办**开展登记」） | 属地省级网信办 | 相对轻，通常**数周**量级（属地初审 + 公示） |

**登记的对象范围**：官方表述限定为「**面向境内公众提供**、且**具有舆论属性或社会动员能力**」的生成式人工智能应用或功能。
本项目是公开可访问的对话式助手，**大概率落在范围内**；但边界判断权在属地 —— 拿你的产品形态去问属地网信办最稳（这也是 §7.2 把"先打电话"排在前面、以及云厂商合规支持很好用的原因）。

> 上面是当前（2026-09）的官方口径；**分类、材料、以及是否需要在属地登记，最终以属地受理口径为准**。

### 7.4 对本项目的影响与可提前准备的东西

- 与 ICP 备案**没有先后依赖**，但**都要时间** → 两条线同时启动；
- AI 侧未走完前：可以**先上线非 AI 功能**（图鉴 / 资产资料 / 预设问答），把对话入口按可见范围收敛 —— 现有的「匿名禁用 AI + 预设问答」正好是现成的收敛手段（`shared/05` §1）；

  - **对话留存可查**：`chat_messages` + 后台「对话记录」页（含导出 CSV）✅
  - **生成内容标识**：AI 回答需带标识（前端展示层面，待做）
  - **投诉 / 举报入口**：待做
  - **用户实名（手机号）**：注册目前无验证码 / 手机号（`shared/05` §2 待办里已记）

### 7.5 个人 / 非盈利主体怎么办

判断标准**不是"盈不盈利"**，而是两条：① **是否向境内公众提供**；② 是否**具有舆论属性或社会动员能力**（面向公众、能产生并传播内容的对话式服务，通常被认为具备）。
《生成式人工智能服务管理暂行办法》明确排除"**未向境内公众提供**生成式 AI 服务的研发与应用"——所以**免费、非盈利都不免除义务**，"**不面向公众**"才是关键分界。

| 服务形态 | 是否触发 |
| --- | --- |
| 仅自己用 / 局域网 / 内测邀请制（不公开注册） | 通常**不适用**（未向境内公众提供） |
| 公开可访问 + 注册登录 + 能对话（本项目形态） | 大概率落在**属地登记**范围 |
| 自研 / 微调模型对外提供 | 国家层面**备案** |

**个人主体的现实障碍**（提前知道，别到提交时才发现）：

- 备案 / 登记材料通常以**单位主体**（营业执照等）为主，个人主体在很多属地不被受理或很难推进；
- ICP 备案侧：个人备案对**交互式服务**（注册登录、发帖评论）多地限制较严，常被要求整改或转企业备案，且不得从事经营性活动；
- 结论：**"个人 + 公开 + 注册 + AI 对话"这个组合，实践上往往推着你用个体户 / 公司主体。**

**三条务实路径**（按成本从低到高）：

1. **先不公开**：内测 / 邀请码 / 白名单 —— 论证"未向境内公众提供"，可先跑起来，等真要公开再办；
2. **个体户 / 公司主体**：ICP 备案 + 属地登记一起办（个体户注册成本低，最省心）；
3. **只开源代码、不运营服务**：别人自己部署自己用，你不提供服务。

**打给属地网信办时，照这四句问**（免费且口径权威，比在网上猜可靠）：

1. 个人开发者调用**已备案**的第三方大模型 API 做公开问答助手（需注册登录），要不要做**生成式 AI 服务登记**？
2. 如果要，**个人主体能不能办**，还是必须企业 / 个体户？
3. 需不需要同时做**安全评估**（舆论属性 / 社会动员能力）？
4. 网站挂在**个人主体** ICP 备案下，注册登录等交互式功能会不会被要求转企业备案？

> 上面是公开规章 + 实践通行理解，**不是法律意见**；分类、材料与主体资格最终以属地受理口径为准。

**本项目当前已落地的"不公开"口径（2026-09-15）**：

| 落点 | 做法 |
| --- | --- |
| 后端 | 主服务 `auth.allow_register=false`（`config.yaml`）→ `POST /api/auth/register` 一律 **403** `本站为不公开邀请制…`；**不是只藏按钮**（藏按钮挡不住直接调接口） |
| C 端 | 登录页去掉注册入口，只留登录 + 邀请制说明（`login.inviteOnly` / `login.inviteHint`） |
| 开户 | 只能由管理员在后台「**用户管理 → 新增用户**」代建，再把用户名/密码转达受邀用户（契约见 `shared/04` §4.4） |
| 仍要注意 | 以上只解决"谁能用"；**只要还挂在大陆公网 + 域名，ICP 备案仍然需要**（见 §7.6 判定表） |

### 7.6 「先不公开」能省掉什么？（两套东西要分开看）

**ICP 备案**（工信部 / 管局）与 **生成式 AI 登记 / 备案**（网信办）是两套独立的东西，"不公开"对它们的作用**不一样**：

| 形态 | ICP 备案 | 生成式 AI 登记 / 备案 |
| --- | --- | --- |
| 本机 / 局域网（如现在的 `192.168.x.x:5173`） | **不需要**（未在境内对外提供互联网信息服务） | **不适用**（未向境内公众提供） |
| 私有组网 / VPN 后访问（Tailscale、ZeroTier、纯内网） | **不需要**（公网不可达） | **不适用** |
| 公网可达 + 邀请码、不推广、不上搜索引擎 | **仍需要** —— 网站本身仍在境内对外提供信息服务，"不推广"不改变这一点 | 可论证"未向公众提供"（**以属地口径为准**） |
| 公网可访问、任何人能注册使用 | 需要 | 需要（属地登记） |

**两条技术现实，别踩**：

1. **大陆服务器 + 未备案域名 = 跑不通**：阿里云等接入商会拦截未备案域名，所以"**大陆 + 域名 + 不备案**"这个组合在实践中不成立（用 IP + 非标端口能临时跑起来，但属灰色状态，被巡检或举报会被要求整改）；
2. **服务放境外 ≠ 免掉 AI 侧义务**：AI 侧按"是否向境内公众提供"判断，**与服务器位置无关**；ICP 备案则确实与接入地有关（境外服务器不需要 ICP 备案）。

> 想低摩擦地先玩起来，最干净的是**前两行**（局域网 / 私有组网）：两套都不用办，也没有任何灰色地带。
> 另外，网站正式上线后还有**公安联网备案**（通常在有 ICP 备案后办），纯自用 / 内网一般不需要。

## 8. 常见坑

| # | 坑 | 后果 | 处理 |
| --- | --- | --- | --- |
| 1 | 域名在**境外注册商**买 | 无法在国内备案 | 直接在阿里云买，或先转入国内注册商 |
| 2 | 备案主体 ≠ 域名持有人 | 备案被退回 | 一开始就统一用同一主体 |
| 3 | 备案期间把域名解析到大陆 ECS | 打不开 + 可能影响审核 | 先用 IP / 局域网联调 |
| 4 | 个人主体做商业运营 | 后续要重新备案 / 补许可 | 有商业化打算直接按企业主体规划 |
| 5 | Nginx 忘关 `proxy_buffering` | **流式对话失效**（一次性刷出） | 见 §5 配置 |
| 6 | 只买 1~5 Mbps 带宽就对外 | 页面与对话卡顿 | 静态上 CDN / 提高带宽 |
| 7 | 忘了 `jwt_secret` 还是占位值 | **任何人可伪造登录** | 见 §6 第一条 |
| 8 | 域名 / 证书忘记续期 | 站点直接下线 | 设到期提醒 + 证书自动续期 |
| 9 | 后台跟着主站一起挂公网 | 内网接口面暴露 | 后台不放公网域名，走内网 / 白名单 |
