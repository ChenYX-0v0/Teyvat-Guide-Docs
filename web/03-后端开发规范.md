# 03 · 后端开发规范

## 1. 目录约定

```
server/
├─ main.go                 # 入口：加载配置 → 初始化 → 启动 → 优雅退出
├─ config/config.yaml      # 配置文件
└─ internal/
   ├─ config/              # Viper 配置结构体与加载
   ├─ router/              # 路由注册与中间件装配
   ├─ handler/             # HTTP 层：绑定参数、调用 service
   ├─ service/             # 业务编排
   ├─ repository/          # 数据访问
   ├─ model/               # GORM 模型
   ├─ dto/                 # 请求/响应结构
   ├─ middleware/          # 中间件
   └─ pkg/
      ├─ logger/           # Zap 日志
      ├─ response/         # 统一响应
      └─ database/         # 数据库初始化
```

## 2. 依赖方向

`router → handler → service → repository → model`，**严格单向**，禁止反向依赖或跨层调用。

- Handler 不得直接调用 repository。
- Service 不得引用 `gin.Context`（只接收 `context.Context` 与领域参数）。
- `pkg/*` 只做基础设施，不得依赖业务包。

## 3. 统一响应

```go
response.OK(c, data)                    // { code:0, message:"ok", data }
response.BadRequest(c, "参数错误")
response.Internal(c, "服务开小差了")
```

结构体：

```go
type Envelope[T any] struct {
    Code    int    `json:"code"`
    Message string `json:"message"`
    Data    T      `json:"data"`
}
```

## 4. 错误处理

- 业务可预期错误：service 返回 `error`，handler 决定 HTTP 状态码。
- 不可预期错误：记录 `logger.L().Errorw(...)` 后返回通用提示，不暴露内部细节。
- 禁止在 handler 里 `panic`（`gin.Recovery()` 仅作兜底）。

## 5. 配置

优先级：环境变量（前缀 `TEYVAT_`，`.` → `_`）> `config/config.yaml` > 默认值。

```powershell
$env:TEYVAT_AI_API_KEY="sk-xxx"
$env:TEYVAT_AI_PROVIDER="openai"
go run ./main.go
```

## 6. 日志

```go
logger.L().Infow("chat finished", "session", id, "cost", d)
logger.L().Errorw("chat failed", "err", err)
```

- `logger.L()` 返回 `*zap.SugaredLogger`，键值对直接写参数（不是 `zap.String`）。
- 调试用 `Debugw`，关键路径 `Infow`，异常 `Errorw`，致命 `Fatalw`。
- 不在日志中打印密钥、完整用户内容。

## 7. 数据库

- 默认 **MySQL**（`127.0.0.1:3306`，`root/root`，库名 `teyvat_guide`），由 `database.Init` 在启动时自动执行 `CREATE DATABASE IF NOT EXISTS`（utf8mb4），无需手动建库。
- 配置项：`driver` / `host` / `port` / `user` / `password` / `name`；`dsn` 留空时由这些字段自动拼装，也可直接写完整 DSN 覆盖。
- 切回 SQLite：设 `database.driver: sqlite` 且 `dsn: data/teyvat.db`（pure-go 驱动，无需 cgo）。
- 表结构变更通过 `AutoMigrate`（在 `router.go` 的 `autoMigrate()` 注册模型），正式项目建议接 `golang-migrate` 管理版本。
- Repository 中 `r.db() == nil` 表示未启用数据库（降级为纯内存逻辑），新增方法请保持该约定。

## 8. 新增接口五步法

1. `internal/dto/xxx.go` 定义出入参。
2. `internal/model/xxx.go` 定义表（如需持久化）。
3. `internal/repository/xxx.go` 写数据访问。
4. `internal/service/xxx.go` 写业务逻辑。
5. `internal/handler/xxx.go` + `router.go` 注册路由。

## 9. AI 能力接入

`service/ai.go` 中定义 `AIClient` 接口（整段补全 + 流式补全）：

```go
type AIClient interface {
    Complete(ctx context.Context, system string, history []Message, prompt string, rc *RequestContext) (string, int, error)
    CompleteStream(ctx context.Context, system string, history []Message, prompt string, rc *RequestContext, onDelta func(text string) error) (int, error)
}
```

- `provider: mock`：无密钥时的兜底实现，返回占位回复，保证本地可跑（流式实现为一次性回调整段文本）。
- `provider: openai`：OpenAI 兼容协议，修改 `base_url` 即可对接其它厂商（暂未接流式协议，同样一次性回调）。
- `provider: remote`：**默认**，对接独立 AI 派蒙服务（`/v1/complete` 与 `/v1/complete/stream`），见 `docs/08-AI服务接入规格.md`。
- 新增供应商：实现接口并在 `NewAIClient` 中分支注册。
- 流式契约、空闲超时与降级语义见 `docs/04-API接口文档.md` §2.2~§2.3；历史组装只允许走 `service/chat.go` 的 `buildHistory`，取历史用 `repository.ListRecentMessages`。

## 10. 玩家查询子模块

- `service/enka/`：Enka.Network 客户端与翻译层（client / model / translate），设计详见 `docs/07-Enka方案设计.md`。
- `service/asset/`：映射数据服务（MySQL 全量加载进内存，Import/Reload），表结构与导入载荷见 `docs/04-API接口文档.md` §6.2。
- `cmd/assetimport/`：批量导入 CLI + 种子 JSON。
- 禁止在代码中硬编码游戏资产名称——一律入映射表（AGENTS.md §7）。
