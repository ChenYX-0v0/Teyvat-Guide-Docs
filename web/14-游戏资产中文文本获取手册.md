## 0. 先分清「键的类型」——这一步决定去哪找

| 缺的东西 | 键 | 只能从哪补 |
| --- | --- | --- |
| 档案里的角色名 / 武器名 | `avatarId` / `weaponId` → `NameTextMapHash` | 主源（id→hash）+ 文本表（hash→中文） |
| **圣遗物「单件名」** | **`NameTextMapHash`（纯 hash，没有 id）** | **只有游戏原表**（`ReliquaryExcelConfigData` / `TextMapCHS`） |
| 圣遗物套装名 | `setId` | 主源 `relics.json.Sets` |
| 圣遗物套装 **效果文案** | ——（**没有**官方文本源） | 人工整理 + wiki 原文逐字核对（`cmd/assetimport/relic_set_effects.json`） |
| 词条名（生命值/暴击率…） | `FIGHT_PROP_*` | `propMap`（资产表） |

> ⚠️ **本手册最重要的一条**：**按名字组织的源（wiki / genshin-db / 百科）永远补不了 hash 键的缺漏** ——
> 它们没有 StableHash 这个维度。必须靠「游戏原表」做 **hash ↔ 游戏内 ID** 的桥。
> 2026-09-26 正是靠这个判断，把 70 条 text 缺漏一次解掉 **54 条**（其余 16 条见 §5 残留）。

## 1. 数据源清单（含实测结论）

| 源 | 取法 | 提供什么 | 实测备注 |
| --- | --- | --- | --- |
| **`EnkaNetwork/API-docs`** | `git fetch` + `git show`（见 §2.1） | `store/gi/` 的 `avatars / weapons / relics / locs / affixes / relic_levels / curves` | **主源**。快照日期与计数见 `../ai/07` TODO-05 §6 |

## 2. Recipe A · 新版本资料更新（常规链路）

### 2.1 拉主源（本机唯一稳的姿势）

> 坑：`raw.githubusercontent.com` **本机不通**；`github.com` 直下大文件会被限速/打断。
> 用 `git fetch` 只取对象，再用 `git show` 抽单个文件，**不动本地工作区**。

```powershell
$repo = 'C:\Users\HONOR\Desktop\API-docs'      # 任意本地克隆/镜像
git -C $repo fetch https://github.com/EnkaNetwork/API-docs.git master
$dst = "$env:TEMP\enka-gi\"; New-Item -ItemType Directory -Force -Path $dst | Out-Null
# 必须走 cmd 重定向：PowerShell 的 > 会写成 UTF-16，JSON 直接废掉
foreach ($f in 'avatars.json','weapons.json','relics.json','locs.json','affixes.json') {
  cmd /c "git -C $repo show FETCH_HEAD:store/gi/$f > `"$dst$f`""
}
```

备选（本次实测可用，小文件更快）：

```powershell
curl.exe -sL -o "$dst\weapons.json" -H 'User-Agent: teyvat-guide/0.1' `
  -H 'Accept: application/vnd.github.raw' `
  "https://api.github.com/repos/EnkaNetwork/API-docs/contents/store/gi/weapons.json?ref=master"
```

### 2.2 生成载荷 + 导入

```powershell
cd C:\Users\HONOR\Desktop\AI提瓦特向导\server
# 本地能连库：
go run ./cmd/assetimport -dir "$env:TEMP\enka-gi"
# 本地连不上库（云端 RDS 只在 VPC 内）→ 只生成 JSON，走管理接口远程导入：
go run ./cmd/assetimport -dir "$env:TEMP\enka-gi" -dump-json "$env:TEMP\gi-payload.json"

$ak = (Select-String -Path ..\.env -Pattern '^TEYVAT_AUTH_ADMIN_KEY=(\S+)').Matches[0].Groups[1].Value
curl.exe -s -X POST -H "X-Admin-Key: $ak" -H 'Content-Type: application/json' `
  --data-binary "@$env:TEMP\gi-payload.json" http://127.0.0.1:18080/api/admin/assets/import
# 关键：带 purgeSnapshots —— 档案快照里存的是旧翻译结果，不清就是脏数据
curl.exe -s -X POST -H "X-Admin-Key: $ak" `
  "http://127.0.0.1:18080/api/admin/assets/reload?purgeSnapshots=true"
```

**导入回执基线**（2026-09-26 那次）：`characters:154 / weapons:255 / relicSets:65 / textMap:444`，
reload 回执 `{reloaded:true, snapshotsPurged:true}`。

### 2.3 CLI 的其它模式（都不改代码）

| 参数 | 用途 |
| --- | --- |
| `-dir <store/gi>` | 全量：角色 / 武器 / 套装 / 文本 |
| `-dump-json <out>` | 与 `-dir` 同用，**只产 payload 不连库** |
| `-textmap-file <TextMapCHS.json>` | **只补** `asset_missing` 里 `kind=text` 的 hash |
| `-import-file <payload.json>` | 任意子集（如 `relicSlots` / `relicSetEffects`） |
| `-affixes-file` / `-stat-weights-file` / `-fight-props-file` | 词缀 / 推荐词条 / 数字枚举映射 |

## 3. Recipe B · 补 hash 键缺漏（本文重点，已验证）

### B1 取当前缺漏清单

```powershell
$ak = (Select-String -Path ..\.env -Pattern '^TEYVAT_AUTH_ADMIN_KEY=(\S+)').Matches[0].Groups[1].Value
curl.exe -s -H "X-Admin-Key: $ak" "http://127.0.0.1:18080/api/admin/assets/missing?limit=500"
```

`kind` 语义：`character` / `weapon` / `relic_set` / `text` / `prop`。
其中 **`text` 只有两个上报点**（`server/internal/service/enka/translate.go`）：
**武器名**（`ITEM_WEAPON`）与**圣遗物单件名**（`ITEM_RELIQUARY`）——定位时先看这两处。

### B2 判定 hash 落在哪张游戏原表（**先自检方法可靠性**）

```powershell
$url = "https://api.github.com/repos/DimbreathBot/AnimeGameData/contents/ExcelBinOutput/ReliquaryExcelConfigData.json?ref=main"
curl.exe -sL -o "$env:TEMP\ReliquaryExcelConfigData.json" -H 'User-Agent: teyvat-guide/0.1' `
  -H 'Accept: application/vnd.github.raw' $url        # 2.77MB
```

> **自检铁律**：先拿**已知**的哈希验一次（如从 `weapons.json`/`avatars.json` 各抽 5 个
> 去 `WeaponExcelConfigData.json` / `AvatarExcelConfigData.json` 里找，**应 5/5 命中**）。
> 否则会把「我的检索方法不对」误判成「表里没有」——2026-09-26 差点栽在这里。

### B3 圣遗物单件名：hash → (setId, equipType) → 套装中文名 → 部位名

代码骨架（完整脚本形态见 `deploy/out/resolve-pieces.js`，注意 `deploy/out/` 不入仓）：

```js
const excel = JSON.parse(fs.readFileSync('ReliquaryExcelConfigData.json', 'utf8'))
const setById = Object.fromEntries(sets.map(s => [s.setId, s.name]))   // 库里 65 套：setId → 中文套装名
const h2 = {}
for (const e of excel) {
  if (!e || !e.nameTextMapHash || !e.setId) continue
  const k = String(e.nameTextMapHash)
  if (!h2[k]) h2[k] = { setId: e.setId, equipType: e.equipType }       // ← 桥就在这里
}
// 部位映射（equipType → genshin-db 字段）
const slotKey = {
  EQUIP_BRACER: 'flower',    // 生之花
  EQUIP_NECKLACE: 'plume',   // 死之羽
  EQUIP_SHOES: 'sands',      // 时之沙
  EQUIP_RING: 'goblet',      // 空之杯
  EQUIP_DRESS: 'circlet',    // 理之冠
}
const g = require('genshin-db')   // 用中文名查（queryLanguages/resultLanguage 都设 ChineseSimplified）
const a = g.artifacts(setById[b.setId], { queryLanguages: ['ChineseSimplified'], resultLanguage: 'ChineseSimplified' })
const name = a[slotKey[b.equipType]].name        // → 「黄金乐曲的变奏」这类真名
```

实测：该表对当时 70 条缺漏 **覆盖 54/70**（其余 16 条不在该表，见 §5）。

### B4 任意文本 hash：`TextMapCHS.json` 直查

47.6MB 全量 `hash → 中文`，**只查缺漏 hash、不全量入库**（`text` 列 `varchar(255)`，
`-textmap-file` 模式本就是"只补缺漏"）。下载（`TextMap/TextMapCHS.json`，同样必须
`Accept: application/vnd.github.raw`；本机慢时可用 `ghproxy.net` 前缀做备选）。

### B5 组装 + 导入 + 验收

```powershell
# 1) 组装 {"textMap":[{"hash":<int>,"text":"中文"}]} → 先本地 ConvertFrom-Json 校验能解析
# 2) 导入
curl.exe -s -X POST -H "X-Admin-Key: $ak" -H 'Content-Type: application/json' `
  --data-binary "@$env:TEMP\textmap-payload.json" http://127.0.0.1:18080/api/admin/assets/import
# 3) 重载（清快照）
curl.exe -s -X POST -H "X-Admin-Key: $ak" "http://127.0.0.1:18080/api/admin/assets/reload?purgeSnapshots=true"
# 4) 验收：档案 warnings 应下降/归零（本次 1 → 0），missing 目标 kind 不再增长
curl.exe -s "http://127.0.0.1:18080/api/genshin/player?uid=<UID>&refresh=true"
```

### B6 仍然解不掉的怎么记

只记在 `asset_missing` 里是**不够定位**的（没有"哪个字段/哪件装备"的上下文）。
建议（未实施）：给 `asset_missing` 增加字段上下文，见 `../ai/07` TODO-05 §7 末段。

### C4 这条路的**边界**

- **没有 hash 维度** → 不能补 `kind=text` 缺漏 ✗（只能按名字对，见 §0）；

  由渲染层文案兜底，**不猜**（详见 `../ai/07` TODO-05 §6/§7）；

## 5. 铁律与坑（都是这轮踩出来的）

1. **先分清键的类型**（§0）——判错键型会白试一整天。
2. **PowerShell 脚本一律 ASCII 写、中文只放 JSON 文件**：PS 5.1 对脚本内中文 + 引号/CRLF 的解析
   极不稳定（`$` 在 CRLF 子串上会漏匹配、`value.Replace` 二次转义等）。
3. **GitHub 原始文件必须 `Accept: application/vnd.github.raw`**，否则返回 HTML 元数据。
4. **wiki 必须带浏览器 UA + Referer**，否则拿到 WAF 空壳页。
5. **大文件别用 `raw.githubusercontent.com`（本机不通）或 github.com 直下（限速打断）** →
   用 `git fetch` + `git show`，或 `api.github.com` raw。
6. **检索方法先自检**（已知哈希应 5/5 命中），再谈"表里没有"。
7. 导入后**必须 `reload?purgeSnapshots=true`**，否则档案快照里还是旧翻译。
8. `textMap` **只补缺漏、不全量入库**（`text` 列 `varchar(255)`）。
9. **查不到就不猜**：宁可让渲染层说「本服暂无该套装的效果资料」/「未知武器」，
   也不凭记忆补（prompt v6 已把该口径写进兜底，见 `../ai/07` TODO-05 §5）。
10. `deploy/out/` **是 gitignored** → 临时脚本不入仓；本文命令要能**独立复制运行**。
