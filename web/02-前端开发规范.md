# 02 · 前端开发规范

## 1. 目录约定

```
src/
├─ api/          # 请求层：每个领域一个文件 + client.ts 拦截器
├─ assets/       # 静态资源
├─ components/
│  ├─ common/    # 与业务无关的通用组件
│  ├─ layout/    # 布局组件
│  └─ <feature>/ # 业务组件（如 chat/）
├─ pages/        # 路由页面，一个路由一个文件
├─ router/       # 路由表
├─ store/        # Zustand store，按领域拆分
├─ hooks/        # 可复用 hooks
├─ types/        # 全局类型
└─ utils/        # 纯函数工具
```

## 2. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 组件文件 | PascalCase | `MessageBubble.tsx` |
| 页面文件 | PascalCase + Page | `ChatPage.tsx` |
| hooks | camelCase + use 前缀 | `useChat.ts` |
| store | camelCase + use 前缀 + Store | `useChatStore.ts` |
| 类型 | PascalCase | `ChatMessage` |
| 常量 | UPPER_SNAKE | `historyLimit` |

## 3. 状态管理

- 全局共享状态（会话、用户、主题）放 `store/`，用 Zustand。
- 组件内局部 UI 状态用 `useState`，**不要**塞进全局 store。
- 服务端数据一律通过 `api/` + store 的 async action 获取，不在组件里直接 `axios`。

```ts
// 推荐：store 暴露动作，组件只调用
const { messages, loading, sendMessage } = useChatStore()
```

## 4. 请求层

- `http` 实例统一在 `api/client.ts` 配置 `baseURL`、`timeout`、错误拦截。
- 后端统一信封用 `unwrap()` 拆箱；非 0 code 直接抛 `Error`。
- 新领域新增文件，例如 `api/wiki.ts`，不要在页面里散落 URL。

## 5. 样式

- 使用 Tailwind 4 原子类，主题色在 `src/index.css` 的 `@theme` 中定义：

```css
@theme {
  --color-teyvat-gold: #d3bc8e;
  --color-teyvat-ink: #0f1720;
}
```

- 条件类名统一用 `clsx`。
- 禁止内联魔法数字颜色，优先主题变量。

### 5.1 移动端（响应式）

断点用 Tailwind 默认值（`sm` = 40rem、`md` = 48rem），**mobile-first**：先写手机端，再用 `sm:` / `md:` 放大。

**硬性要求（2026-09-14 真机问题后定）**：

1. **导航不能只在桌面存在**：主导航项只写在 `src/components/layout/navItems.ts`，桌面侧栏 `Sidebar` 与移动端抽屉 `MobileNav` 共用同一份。**禁止只往 `Sidebar` 加项**——那必然出现"桌面有、手机没有"（历史问题：手机端登录后完全没有导航入口）。
2. **抽屉不能放在带 `backdrop-blur` / `transform` / `filter` 的祖先里**：这些属性会为 `position: fixed` 后代创建包含块，抽屉会被关在局部容器内（`MobileNav` 因此渲染在 `AppLayout` 中、`Header` 之外）。
3. **输入类元素移动端字号 ≥16px**（写 `text-base sm:text-sm`）：iOS 聚焦更小字号的输入框会自动放大整页。
4. **页面高度用 `h-dvh`**（不要 `h-full` / `100vh`）：移动端地址栏伸缩时 `100vh` 会高于可视区、底部被裁；底部固定元素补 `pb-[max(1rem,env(safe-area-inset-bottom))]`。
5. **可复用的列表/面板必须同时给移动端入口**：如历史会话（`SessionList`）桌面是常驻侧栏、移动端用 `variant="drawer"` 放进抽屉，不能变成"手机上不可达的功能"。
6. **抽屉交互三件套**：能开、能关（遮罩点击 / `Esc` / 路由变化）、开着时背景不滚动（`touch-none` + 锁 `body` 滚动）。
7. 改动布局后按 **375 / 390 / 414** 三档宽度过一遍。
8. **可折叠区块用同一套写法**（2026-09-21 定，先例：账号页「账号信息行」「玩家头部卡」）：触发元素用 `<button>` + `aria-expanded` + `aria-label={展开/收起}`（文案复用 `common.expand` / `common.collapse`）；指示器用 `▾`，展开时 `rotate-180`。两条硬约束：① **只折"详情/次要操作"**——主操作不折（如账号页未绑定时的查询表单必须直接可见）；② 列表项的选中态用 **`border-transparent` 而不是去掉边框**，避免切换时尺寸跳动。

## 6. 类型与 i18n

- 接口出入参定义在 `src/types/index.ts` 或就近 `types.ts`。
- 禁止 `any`；确需时用 `unknown` + 类型收窄。
- 环境变量类型声明在 `src/vite-env.d.ts`。
- **UI 文案禁止硬编码**：一律写入 `src/i18n/zh-CN.ts`（基准，key 有编译期检查）与 `en.ts`，组件用 `t('key', { 插值 })`。

## 7. 提交前的检查

```powershell
npm run lint
npm run build
```

## 8. 新增页面的三步

1. `src/pages/XxxPage.tsx` 写页面。
2. `src/router/index.tsx` 注册路由，需要入口时在 `components/layout/navItems.ts` 加导航项（**桌面侧栏与移动端抽屉共用这一份**，不要只加一边，见 §5.1 第 1 条）。
3. 如需数据：`src/api/xxx.ts` → `src/store/useXxxStore.ts` → 页面消费。
