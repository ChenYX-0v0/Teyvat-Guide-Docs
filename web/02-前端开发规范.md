# 02 · 前端开发规范

## 1. 目录约定

```
src/
├─ api/          # 请求层：每个领域一个文件 + client.ts 拦截器
├─ assets/       # 静态资源
├─ components/
│  ├─ common/    # 与业务无关的通用组件
│  ├─ layout/    # 布局组件
│  └─ <feature>/ # 业务组件（如 chat/）
├─ pages/        # 路由页面，一个路由一个文件
├─ router/       # 路由表
├─ store/        # Zustand store，按领域拆分
├─ hooks/        # 可复用 hooks
├─ types/        # 全局类型
└─ utils/        # 纯函数工具
```

## 2. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 组件文件 | PascalCase | `MessageBubble.tsx` |
| 页面文件 | PascalCase + Page | `ChatPage.tsx` |
| hooks | camelCase + use 前缀 | `useChat.ts` |
| store | camelCase + use 前缀 + Store | `useChatStore.ts` |
| 类型 | PascalCase | `ChatMessage` |
| 常量 | UPPER_SNAKE | `historyLimit` |

## 3. 状态管理

- 全局共享状态（会话、用户、主题）放 `store/`，用 Zustand。
- 组件内局部 UI 状态用 `useState`，**不要**塞进全局 store。
- 服务端数据一律通过 `api/` + store 的 async action 获取，不在组件里直接 `axios`。

```ts
// 推荐：store 暴露动作，组件只调用
const { messages, loading, sendMessage } = useChatStore()
```

## 4. 请求层

- `http` 实例统一在 `api/client.ts` 配置 `baseURL`、`timeout`、错误拦截。
- 后端统一信封用 `unwrap()` 拆箱；非 0 code 直接抛 `Error`。
- 新领域新增文件，例如 `api/wiki.ts`，不要在页面里散落 URL。

## 5. 样式

- 使用 Tailwind 4 原子类，主题色在 `src/index.css` 的 `@theme` 中定义：

```css
@theme {
  --color-teyvat-gold: #d3bc8e;
  --color-teyvat-ink: #0f1720;
}
```

- 条件类名统一用 `clsx`。
- 禁止内联魔法数字颜色，优先主题变量。

## 6. 类型与 i18n

- 接口出入参定义在 `src/types/index.ts` 或就近 `types.ts`。
- 禁止 `any`；确需时用 `unknown` + 类型收窄。
- 环境变量类型声明在 `src/vite-env.d.ts`。
- **UI 文案禁止硬编码**：一律写入 `src/i18n/zh-CN.ts`（基准，key 有编译期检查）与 `en.ts`，组件用 `t('key', { 插值 })`。

## 7. 提交前的检查

```powershell
npm run lint
npm run build
```

## 8. 新增页面的三步

1. `src/pages/XxxPage.tsx` 写页面。
2. `src/router/index.tsx` 注册路由，需要入口时在 `Sidebar.tsx` 加导航项。
3. 如需数据：`src/api/xxx.ts` → `src/store/useXxxStore.ts` → 页面消费。
