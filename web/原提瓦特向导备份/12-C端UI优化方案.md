# 12 · C 端 UI 优化方案

> **用途**：C 端（用户可见页面）的体验优化清单、优先级与**验收标准**。
> ⚠️ **当前方向（2026-09-20 确认）**：**优先做"视觉设计层面"**（配色 / 质感 / 排版 / 卡片层级 / 动效），
> 交互类改动（下方 P0-1 停止生成、P0-2 消息级操作 —— 曾实现后按用户要求撤回）**暂缓**。
> 视觉工作的落地顺序见 §6「视觉设计方案」。
> **体检依据**：2026-09-20 对 `web` 仓代码的逐项核对（页面 / 组件 / 样式 / 交互 / 可达性），结论带文件证据。
> **定位**：**这不是"改配色"，而是"补体验闭环 + 建设计系统"**。挂载在 `06-开发路线图.md §P2`。
> **取舍原则**：先让用户**敢信 + 顺手**，再谈**好看**；不用组件库，用自有 token 抽基元。

## 2. 两条主张

> **原「2.1 让用户敢信：把依据可视化（游戏资料依据卡片）」已于 2026-09-20 取消** —— 用户判断必要性不足，理由见 §4。
> ⚠️ 取消的只是**前端那张展示卡片**；后端「资料注入」机制**不受影响**（它服务于回答质量，与是否把依据摊开给用户看无关）。

### 2.1 让用户「顺手」：补完对话页闭环
停止生成 → 重新生成 → 复制 → 失败重试。四件事都是刚需，其中"失败即重问"还会**重复消耗 token**（要花钱）。

### 2.2 去掉「复制粘贴」：把设计系统做实
不引入 antd/shadcn（风格迁移成本高、依赖大），而是用自有 token 抽 **5 个基元**：`Button / Card / Input / Dialog / Toast`。
提瓦特风的表达统一为：**3 级面板 + 2 级描边 + 1 套金色发光 + 七元素色点缀**（元素色是原神 UI 的天然识别资产）。

## 3. 优先级与验收标准

### P0 · 体验缺口（先做，预计 0.5~1 天）

| # | 项 | 做法 | 验收标准 |
| --- | --- | --- | --- |
| **P0-1** | **停止生成** | store 持 `AbortController`；把 `stream()` 已有的 `signal` 接上；生成中"发送"变"停止" | 生成中点停止 → 请求立即中断、**已产出内容保留**并有"已停止"提示；不产生重复落库 |
| **P0-2** | **消息级操作** | 助手消息下方常驻操作条：**复制 / 重新生成 / 失败重试**；重新生成先移除该条再重发同一条提问 | 复制可粘贴出原文；重新生成产生**新回复且不叠加旧回复**；失败消息点重试可恢复；窄屏（375）下操作可达 |
| **P0-3** | **焦点可见 + 基础可达性** | 统一 `focus-visible:ring`；图标按钮补 `aria-label`；自查文字对比度 | Tab 走一遍全站**能看见焦点**；关键图标按钮有可读的无障碍名 |
| P0-4 | 文案归 i18n | 清理 `'Traveler'`、圣遗物位名等硬编码 | 组件内不出现中文字面量（除 i18n 词表） |

### P1 · UI 基建（地基，预计 1.5~2 天）

| # | 项 | 做法 | 验收标准 |
| --- | --- | --- | --- |
| P1-1 | **设计 token 扩充** | `@theme` 增补字体 / 间距 / 圆角 / 层级 / 状态色；收敛散落的 `white/5`、`black/20` | 全站颜色只来自 token（`rg` 抽查类名） |
| P1-2 | **5 个基元组件** | `components/common/`：Button / Card / Input / Dialog / Toast；替换 ≥6 处重复卡片 | 重复卡片 class 归零；视觉与交互一致 |
| P1-3 | **反馈体系** | 骨架屏（列表/档案/会话）+ 统一 Toast（成功/失败/复制成功） | 首屏与列表加载不再出现"加载中…"裸文案 |
| P1-4 | **首屏性能** | 路由级 `React.lazy` + `Suspense`（wiki/account 先懒加载） | 主包体积下降（目标 **< 250KB**）。✅ `web/dist/` 本就已在 `.gitignore`，无需处理 |

### P2 · 产品差异化（预计 1~2 天；原 P2-1「资料依据卡片」已取消，见 §4）

| # | 项 | 做法 | 验收标准 |
| --- | --- | --- | --- |
| P2-1 | **图鉴页（wiki）** | 用**现有只读接口** `/api/genshin/*`（`web/04` §2）：列表 + 筛选 + 详情（页面骨架与视觉已在视觉改造第 3 批就位） | 从 `/wiki` 能查到真实角色/武器/套装数据，非占位 |
| P2-2 | i18n 无刷新切换 + 清理残留 | locale 放入 Zustand（`i18n/index.ts` 注释已给改法） | 切换语言不刷新页面，全站即时生效 |

### P3 · 后置（等备案/正式上线后再看）

PWA（离线 + 添加到主屏）· 深色/浅色主题切换 · 配队推荐器 · 采集路线地图。

## 4. 明确先不做（省精力）

| 别做 | 原因 |
| --- | --- |
| **「游戏资料依据」卡片**（原 `2.1` / 原 `P2-1`） | **2026-09-20 决策取消**：必要性不足 —— 答案本身已把结论讲清，再挂一份"依据"反而增加阅读负担。附带好处：它是本方案里**唯一需要后端配合**的一项，去掉后**前端可完全独立推进**（图鉴页用现成的只读接口即可）。⚠️ 后端资料注入机制不动 |
| 现在做深色/浅色切换 | 只有一套深色，做切换 = 双倍回归成本，对核心目标零帮助 |
| 引入 antd / shadcn | 风格迁移成本高、依赖大；缺的只是 5 个基元 |
| 为动画而动画 | `framer-motion` 装了 0 用；要么用在"抽屉/消息入场"等有意义处，要么卸掉 |
| 大改视觉配色 | 金色 + 深色方向是对的，**要系统化，不要推翻** |
| PWA | 有正式域名 + HTTPS 之后才有意义（备案未完成前不排） |

## 6. 视觉设计方案（2026-09-20 提出，**待确认后落地**）

> 方向已确认：**视觉设计层面**（配色 / 质感 / 排版 / 卡片层级 / 动效）。本节给**可直接落地的 token 值**与页面要点。

### 6.1 现状视觉诊断（据代码）

| 问题 | 证据 | 后果 |
| --- | --- | --- |
| 颜色 token 只有 5 个，其余靠**临时不透明度** | `@theme` 仅 `gold / gold-deep / ink / panel / panel-soft`；而 `white/5`、`white/10`、`black/20`、`white/40·45·60·85` 散落各处 | 层级不可控，越改越乱 |
| 面板**只有一层** | 卡片、侧栏、输入区、抽屉都用 `bg-teyvat-panel/70` | 没有纵深，界面"平" |
| **无字号阶、无间距节奏** | `text-xs/sm/base` + `font-medium` 随手用 | 缺阅读节奏，标题/正文/注释分不清 |
| **无材质、无发光、几乎无阴影** | 全站鲜有 `shadow-*`，卡片无顶缘高光 | 卡片像"色块"而非"物件" |
| 动效只有 2 个 CSS 动画 | `animate-bounce`（等待三点）、`animate-spin`；`framer-motion` **0 使用** | 无入场/状态过渡 |
| 品牌资产没用上 | 元素色、稀有度色数据里都有（`RelicDetailCard` 已做分级着色） | 少了原神辨识度 |

### 6.2 方向：深色《提瓦特》材质语言

### 6.5 动效原则（只做三处）

① 页面/卡片**入场**：fade + 8px 位移，150~200ms；② 悬停/聚焦**过渡**：120~160ms；③ 流式生成的**呼吸光标**。
其余（列表错位入场、按钮弹跳、页面转场）**一律不做** —— 少而准才显得专业。

### 6.6 落地顺序与验收自检

顺序：**① 写 tokens（`index.css`）→ ② 抽 3 个基元（Card/Panel、Button、Badge）→ ③ 页面套用（首页 → 对话页 → 侧栏 → 登录 → 账号）→ ④ 全站自检**。

验收自检 6 条：① 颜色只来自 token；② 面板只有 3 级（`panel` / `panel-soft` / `raised`）；③ 文字只有 4 级（`text` / `text-2` / `text-3` / `text-4`）；④ **圆角按用途固定** —— 卡片 `rounded-2xl`、按钮与输入 `rounded-xl`、小徽记 `rounded-md`、标签 `rounded-full`（未强行把 Tailwind 默认刻度收敛成 3 档，避免与全局默认值冲突）；⑤ 金色只出现在"强调"位置（主按钮/焦点/选中）；⑥ **中性透明叠加只用白名单的几档** —— `white/[0.03]`·`white/[0.04]`·`white/5`（输入底 / 悬停）、`black/20`·`black/25`·`black/60`（栏底 / 遮罩），不再是"随手取一个透明度"。
