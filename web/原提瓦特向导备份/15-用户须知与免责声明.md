## 3. 执行机制：每个用户都必须读

| 环节 | 实现 | 位置 |
| --- | --- | --- |
| **触发** | 登录后 `GET /api/auth/me` 下发 `terms.currentVersion`；与 `terms.acceptedVersion` 不一致 → **不渲染任何页面内容**，只渲染阻断式弹窗 | `web/src/components/layout/AppLayout.tsx` |
| **不可绕过** | 弹窗无法关闭：不响应 Esc、不响应点遮罩、无关闭按钮；只有「我已阅读并同意」/「不同意并退出登录」 | `web/src/components/common/Modal.tsx`（`blocking` 模式）+ `components/legal/TermsModal.tsx` |
| **强制阅读 5 秒** | 确认按钮在 5 秒内保持禁用，并显示剩余秒数 | `TermsModal.tsx` 的 `READ_SECONDS = 5` |
| **确认留痕（后端存列）** | `POST /api/auth/terms {version}` → 写 `users.terms_version` / `users.terms_accepted_at`（**服务端时间戳，可举证**） | `handler/auth.go` → `service/terms.go` → `repository/user.go` |
| **服务端校验** | 只接受与 `CurrentTermsVersion` **完全相等**的版本；旧页面/伪造请求 → 400（`ErrTermsVersionInvalid`） | `service/terms.go` |
| **公开可见** | 另有**免登录**的完整条款页 `/terms`（审核人员、未登录用户可直接阅读）；页脚常驻入口 | `pages/TermsPage.tsx` + `router/index.tsx` + `components/layout/SiteFooter.tsx` |
| **可观测** | 埋点 `terms_shown` / `terms_accepted`（只带版本号，不带任何用户输入） | `lib/track.ts` + 主服务白名单 `usageEventProps` |

### 3.1 改条款文案的 SOP（重要）

1. 改 `web/src/components/legal/TermsContent.tsx`（文案）+ 本文档 §2（存档）；
2. **同步递增** `server/internal/service/terms.go` 的 `CurrentTermsVersion`（如 `v1.1-2026xxxx`）；
3. 发布 → **所有用户下次进入时会被要求重新阅读并确认**（这是刻意的：否则用户"同意"的是旧条款）；
4. 本文档补一条变更记录（见 §5）。

> 为什么版本号必须放服务端：前端的版本号可被绕过/缓存，服务端才是"当前有效条款"的唯一真源；
> 用户已同意的版本存列而非 localStorage，换设备/清缓存不会重复弹，且留有服务端时间戳。
